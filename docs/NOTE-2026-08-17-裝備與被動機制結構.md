# 0. 結論先講

### ① 純數值裝備的邊際價值**不是線性的，也不是單調的**

🟢 桃太郎 ATK 60 對 DEF 20 的敵人 → 每刀 40。`units.txt` 的 kill-target ladder 是 80/120/160/240。

| ATK 加值 | 每刀 | 80 | 120 | 160 | 240 | **被平移的階梯數 `S`** | 邊際 `ΔS` |
|---|---|---|---|---|---|---|---|
| +0 | 40 | 2 | 3 | 4 | 6 | — | — |
| **+10** | 50 | 2 | 3 | 4 | **5** | **1** | +1 |
| 🔴 **+20** | 60 | 2 | **2** | **3** | **4** | **3** | **+2** |
| +30 | 70 | 2 | 2 | 3 | 4 | **3** | **0** |
| +40 | 80 | **1** | 2 | **2** | **3** | **4** | +1 |

> 🔴 **ATK+30 與 ATK+20 完全等價，而 ATK+20 是 ATK+10 的三倍。**
> 「+10 是 +20 的一半」這個直覺**完全錯誤**，而它正是一般 RPG 裝備定價的預設心智模型。
>
> 🟢 而 [H16](NOTE-2026-08-16-H16-GDD技能豁免券檢核.md) 已量到刀數是**懸崖**（2 刀 68% → 3 刀 1%）。
> **所以一件 ATK+20 的飾品會把一個 1% 的遭遇變成 68% 的遭遇。那不是強化，是換一款遊戲。**

### ② DEF 裝備的危險來自 `max(1, ATK−DEF)` 的地板，而正守的餘裕只剩 **30**

🟢 `傷害 = max(1, ATK − DEF)`（OD-05）。當 `DEF ≥ 敵方 ATK`，傷害鎖死為 1。

```
免疫餘裕(u)  =  ATK_敵  −  DEF_u
```

| 角色 | DEF | 對 kohaku (100) | 對 sc_bruiser (85) | 對 sc_shield (70) |
|---|---|---|---|---|
| 🔴 **正守** | **70** | **+30** | **+15** | 🔴 **+0（已經免疫）** |
| 桃太郎 | 50 | +50 | +35 | +20 |
| 玄真 | 35 | +65 | +50 | +35 |
| 影丸 | 30 | +70 | +55 | +40 |

> 🔴 **一件 DEF+15 的裝備讓正守對 `sc_bruiser` 免疫。**
> 🟢 而 `units.txt:393` 寫得很清楚，那隻敵人存在的**唯一理由**就是
> 「ATK 85 hurts Genjin (50 a hit) and barely scratches Masamori (15),
> so WHO holds this lane is a real answer」——
> **DEF+15 把 15 變成 1，那條 lane 的設計意圖當場歸零。**
>
> 這正是 T1 §5.3 的 **FM-1（Juggernaut）**：一件飾品就能觸發。

### ③ 動詞覆蓋率指數可以直接用**既有的**儀器量，而且它有一個關鍵性質

🟢 `LegalCommands.For(state, unit)` 已經存在並已被使用
（`PositionSolver.cs:152`：`analysis.LegalActionCount = legal.Count`）。

```
VCI(u,s) = |{ 指令型別 v : 至少存在一個合法的 v 指令 }|        動詞廣度
TCI(u,s) = Σ_v |{ v 的合法目標 }|   （排除 MoveCommand）      目標深度
```

| 裝備型別 | ΔVCI | ΔTCI | `S`（階梯平移） |
|---|---|---|---|
| **解鎖型**（賦予擊退/反擊/破甲） | **+1** | +k | 0 |
| **擴張型**（射程+1、推撞距離+1） | 0 | **+k** | 0 |
| 🔴 **純數值型**（ATK/DEF/HP） | **0** | **0** | 🔴 **可達 3** |

> 🔴 **這是本檔最重要的結構觀察**：
> **純數值裝備在「選擇數」這個儀器上完全隱形（ΔVCI = ΔTCI = 0），
> 卻正是唯一能把 3 個階梯一次抹平的東西。**
>
> **測「增加了多少選擇」的儀器，看不見「摧毀了多少區分度」。兩把尺都要用。**

### ④ 裝備可以在**不改任何 Core 規則、不動 A4** 的情況下加進來

🟢 `UnitDef` 是 `readonly` 且共享不可變（`UnitDef.cs:6-13`：「Shared and immutable — UnitState holds a reference, clones share it」）。
🟢 而 `AtkGrowth` 已經示範了正確的做法（`UnitDef.cs:53-58`）：
「derived from the round counter instead of stored on UnitState: **adds nothing to clone, nothing to the state hash**」。

> 🟡 **若裝備在戰鬥中不可更換**（只在 encounter 載入時決定），
> 那麼「基礎 UnitDef ＋ 裝備」可以在**載入期**合成成一個新的不可變 `UnitDef`。
> **執行期沒有任何新狀態、hash 完全不需要改、沒有 encounter 的 golden hash 會失效**
> （沒寫 `equip=` 的 encounter 合成出完全相同的 UnitDef）。
>
> 🟢 **而且現行 `UnitDef` schema 已經足以表達綠燈清單的大部分**：
> 射程（`AttackRange`）、賦予反擊（`CounterApCost`）、賦予擊退/遲滯/嘲諷/破甲（各自的 `ApCost`）
> **全部是既有欄位。** 需要新欄位的只有免疫遲滯與地形減免（§5.3）。

# 1. 現況盤點 🟢

## 1.1 目前沒有裝備系統，而「變體單位」是它的替身

🟢 `units.txt` 目前用**一整行新的 `unit id=`** 來表達每一個變體：
`momotaro_push` / `momotaro_ap5` / `momotaro_r2` / `Momotaro_A` / `Momotaro_B` /
`momotaro_pure` / `momotaro_ripo` / `momotaro_push_g5` / `momotaro_push_c1..c5` …

**這個做法在 2 個裝備欄位就會崩潰** 🟡：

```
定義數  =  8 個基底（4 角色 × 2 定位）  ×  n^k     （k 欄位、每欄 n 件）

k=2, n=4  ->    8 × 16  =   128 行
k=3, n=5  ->    8 × 125 = 1000 行
```

> 🟢 `units.txt` 目前約 450 行 / 約 50 個單位就已經需要大量註解維護。
> **1000 行的組合展開不是「比較麻煩」，是不可行。**
> **所以引入裝備欄位這件事本身就強制要求合成機制（§4.4），不能再靠加行。**

## 1.2 既有的三個「正確做法」範例 🟢

| 範例 | 位置 | 它示範了什麼 |
|---|---|---|
| **`AtkGrowth`** | `UnitDef.cs:53-58` | 從既有狀態**推導**而非儲存 → 零 clone 成本、零 hash 成本 |
| **回合戳記**（`SlowedUntilTurn` / `ArmorBrokenUntilTurn`） | `BattleState.cs:28-35` | 「戳記而非倒數」→ **沒有 tick 就沒有順序可以搞錯** |
| **hash 分段閘門** | `StateHasher.cs:80,95,109` | `if (state.HasArmorBreak) {...}` → **沒用到該機制的戰鬥 hash 完全不變**，golden 常數繼續有意義 |

> 🟡 **這三個模式合起來就是裝備系統的完整架構藍圖**，§4.4 直接沿用。

# 2. 核心衝突：裝備要買的是「新問題」，不是「更好的答案」

🟢 `units.txt:77-88` 已經把這條原則寫進控制組的設計理由裡：

> 「A pure damage skill also fails the standard test for an interesting choice —
> **better than the basic attack makes it the new only answer, worse makes it dead weight.**」

🟡 裝備面對的是同一條測試，但更嚴重，因為**裝備是永久的**：

| | 技能 | 裝備 |
|---|---|---|
| 何時生效 | 花 AP 才生效，每次都要重新決定 | **永久生效，一次決定** |
| 錯誤定價的後果 | 該技能沒人用（可回收） | 🔴 **所有關卡的數值基準永久平移** |
| 對量測的影響 | 可用「有技能/無技能」A/B 隔離 | 🔴 **裝上之後所有既有基準失效** |

> 🟡 **技能的定價錯誤是可逆的，裝備的定價錯誤是結構性的。**
> 這就是為什麼裝備需要一份紅燈清單，而技能只需要一次掃描。

# 4. 數學模型

## 4.1 刀數階梯平移風險（Step-Shift Risk） 🟡

令敵人 HP 集合為階梯 `L = {H₁ … Hₙ}`，玩家每刀 `D = max(1, ATK − DEF_敵)`。

```
S(b)  =  | { H ∈ L :  ceil( H / (D+b) )  <  ceil( H / D ) } |
```

🟢 帶入 `L = {80, 120, 160, 240}`、`D = 40`，即 §0① 的表。三個性質值得寫下來：

| 性質 | 內容 |
|---|---|
| **非線性** | `S(10)=1`、`S(20)=3` —— 加倍投入換到三倍效果 |
| 🔴 **非單調（邊際）** | `S(20)=S(30)=3` —— **ATK+30 相對 +20 的邊際價值是 0** |
| **與階梯結構綁死** | `S` 完全取決於 `L` 的組成。**換一組敵人，同一件裝備的價值完全不同** |

**價值換算** 🟡：🟢 [H16](NOTE-2026-08-16-H16-GDD技能豁免券檢核.md) 量到 2 刀 → 3 刀使勝率 68% → 1%。
把它當作單階的量級：

```
一件平移 3 階的裝備  ≈  把數個遭遇從「幾乎不可能」直接搬到「輕鬆」
```

> 🔴 **這就是「純數值裝備摧毀關卡整除性」的精確意思**：
> 它不是讓關卡「稍微簡單」，而是**讓關卡設計師精心挑選的那個刀數失去意義**。
> 🟢 而那個刀數正是 `units.txt:160-183` 整個 kill-target ladder 存在的理由。

## 4.2 DEF 側：地板效應與 Juggernaut 邊界 🟡

```
受傷(u, j)  =  max(1, ATK_j − DEF_u)

免疫條件    :  DEF_u  ≥  ATK_j
Juggernaut  :  DEF_u  ≥  max_j ATK_j      （對全體免疫）
```

🟡 DEF 的危險與 ATK 不同：**ATK 是階梯效應（跳躍），DEF 是地板效應（斷崖）**。
在 `DEF < ATK` 的區間裡 DEF 是線性有效的；**一旦越過 `ATK`，價值瞬間變成無限大**（傷害鎖 1）。

**T1 §5.3 的 FM-1 已經指認過這個故障，本檔補上它的觸發距離**：

| 角色 | 距離「對 Stage 01 主力敵人免疫」還差多少 DEF |
|---|---|
| 🔴 **正守** | **30**（且對 `sc_shield` 已經是 0） |
| 桃太郎 | 50 |
| 玄真 | 65 |
| 影丸 | 70 |

> 🔴 **正守的餘裕不到桃太郎的一半，而他恰好是最可能被裝上防禦裝備的角色。**
> 這是「符合角色幻想的裝備選擇」與「立刻觸發 Juggernaut」重合的一格。

## 4.3 動詞覆蓋率指數（VCI / TCI） 🟡

🟢 現行指令型別共 10 種（`BattleSimulator.cs:62-70`）：
`Move / Attack / Guard / Taunt / Slow / Push / ArmorBreak / Purify / Rest / Wait`

```
VCI(u,s)  =  |{ 指令型別 v : LegalCommands.For(s,u) 中至少有一個 v }|
TCI(u,s)  =  Σ_v  |{ v 的合法目標 }|        排除 MoveCommand
```

> 🟡 **為什麼必須排除 Move**：可達格在開闊地約 25 格，會淹沒其餘所有動詞（各 1–4 個目標）。
> 不排除的話 `LegalActionCount` 量到的其實是「這格有多空曠」，不是「有多少戰術選擇」。
> 🟢 這也是 `PositionSolver.cs:153` 的 `LegalActionCount` 目前**不適合直接當 VCI 用**的原因。

**現行角色的 VCI** 🟢：

| 單位 | 動詞 | VCI |
|---|---|---|
| `momotaro`（無技能） | Move, Attack, Guard, Rest, Wait | **5** |
| `momotaro_push` / `zhengshou_taunt` / `kagemaru` / `Genjin_B` | ＋各自 1 個 | **6** |

**射程對 TCI 的效果** 🟡（菱形內格數 `2r² + 2r`）：

| 射程 | 可及格數 | 相對 r=1 |
|---|---|---|
| 1 | 4 | 1× |
| 2 | 12 | **3×** |
| 3 | 24 | **6×** |

> 🔴 **但射程裝備有一條陣營相依的紅線**：
> 🟢 R-GRID-06 明文「**由於方格四鄰接且近戰射程 = 1**，`Exposure(c)` 等於同一回合最多有幾隻敵人能攻擊站在 `c` 的單位」。
> 🟢 `units.txt:193-196` 也獨立指出過：「range 1 means Exposure == adjacent passable cells. **Range 2 breaks that identity.**」
>
> **給玩家射程 = 綠燈**（Exposure 量的是承受的威脅，玩家射程不影響它）。
> 🔴 **給敵人射程 = 破壞 M4**，而 M4 是主假說唯一能證偽的驗收線（[exposure.md](02-design/exposure.md)）。

## 4.4 架構：零 hash 成本的裝備合成 🟡

**核心約束** 🟢：`UnitDef` 是 `readonly` 共享不可變。所以裝備**不能**改 `UnitDef`，只能：

| 方案 | 何時需要 | 新 hash 欄位 | 既有 golden hash |
|---|---|---|---|
| **A. 載入期合成** —— encounter 寫 `spawn ... equip=a,b`，loader 合成出一個新的不可變 `UnitDef` | 裝備**戰鬥中不可更換**時 | ✅ **零** | ✅ **完全不受影響** |
| B. `UnitState` 上的可變修飾層 | 需要戰鬥中換裝／損壞／消耗時 | 🔴 需要，且須加 hash 閘門 | 🔴 需重新產生 |

> 🟡 **建議方案 A。** 它甚至不需要動 `BattleSimulator` —— 這是一個**載入器功能**，不是規則層功能。
> 沒有 `equip=` 的 encounter 合成出位元相同的 `UnitDef`，
> 🟢 因此所有既有 encounter 的 A4 golden hash **一個都不會變**。
>
> 這與 `AtkGrowth` 的哲學一致（`UnitDef.cs:53-58`），也與 `StateHasher` 的閘門模式一致
> （`StateHasher.cs:80/95/109`：沒用到就不進 hash）。

**方案 A 的一條硬約束** 🟡：**合成必須是順序無關的**，否則
`equip=a,b` 與 `equip=b,a` 會產生不同的 `UnitDef` → 不同 hash → 決定論破裂。

```
安全：加法（ATK+10 ＋ ATK+5 = +15）、取最大（射程）、布林 OR（免疫）
🔴 危險：乘法與加法混用、有先後的覆寫（「設為 X」）
```

> 🟡 **白皮書規則 E1：裝備效果必須是可交換的（commutative）。**
> 「設定為 X」型效果一律禁止，因為它讓合成順序變成規則的一部分。

# 5. 裝備與被動設計白皮書

> ⚠️ **以下全部是提案，不裁決任何 OD。** 引入裝備欄位本身需要新的 OD。

## 5.1 🟢 綠燈：安全動詞

判準：**`S = 0`（不平移任何階梯）且（`ΔVCI ≥ 1` 或 `ΔTCI > 0`）**

| 效果 | 型別 | 現行欄位 | ΔVCI | 備註 |
|---|---|---|---|---|
| **射程 +1**（玩家單位） | 擴張 | 🟢 `AttackRange` | 0 | TCI ×3。🔴 **僅限玩家**，見 §4.3 |
| **賦予反擊** | 解鎖 | 🟢 `CounterApCost` | +1 | ⚠️ 先讀 T1 §4.5：現行數值下反擊穿不過階梯，先修穿越能力再發裝備 |
| **賦予擊退／遲滯／嘲諷／破甲** | 解鎖 | 🟢 各自 `ApCost` | +1 | 全部是既有欄位，零程式成本 |
| **免疫擊退** | 規則改寫 | 🟢 `ImmuneToPush` | 0 | 已存在（正守／玄真） |
| **免疫遲滯** | 規則改寫 | 🔴 需新欄位 | 0 | 直接對抗 T3 §4.4 的威脅面積 −59% |
| **地形成本減免**（森林/泥沼 −1） | 擴張 | 🔴 需新欄位 ＋ 動 `MovementCalculator` | 0 | 改變可達集合 → TCI 上升。**不碰傷害** |
| **MOVE +1** | 擴張 | 🟢 `Move` | 0 | §1.3 確認確實有效。但注意「移動後仍能攻擊」上限由 AP 決定（T3 §4.4），MOVE+1 只在 MOVE < 4 時有感 |
| **AP 上限 +1／回復 +1** | 經濟 | 🟢 `MaxAp` / `ApRegen` | 0 | 🔴 **必須等 T5**。T1 §4.6 已證明 AP 上限與動作數上限直接相關 |

## 5.2 🔴 紅燈：嚴格禁止

判準：**`S > 0`，或破壞既有的量測不變量**

| 效果 | 為什麼禁止 |
|---|---|
| 🔴 **裸 ATK 加值** | §4.1：`S` 非線性且非單調，+20 一次平移 3 階 ≈ 把 1% 遭遇變成 68% |
| 🔴 **裸 DEF 加值** | §4.2：地板效應。正守只差 **30** 就全體免疫，差 **15** 就讓 `sc_bruiser` 的設計意圖歸零 |
| 🔴 **敵方單位的射程加值** | §4.3：破壞 R-GRID-06 的 Exposure 恆等式 → **M4 驗收線失效** |
| 🔴 **額外行動／額外回合／行動次數** | T1 §5.3 **FM-5**：任何行動次數乘數都是超線性的（FFT 速度問題）。**這是最硬的一條紅線** |
| 🔴 **傷害百分比減免** | 與減法傷害模型（OD-05）混用會產生 `max(1, ·)` 之外的第二個地板，且讓刀數變成非整數推理 |
| 🔴 **「設定為 X」型效果** | §4.4 E1：破壞合成的可交換性 → 破壞決定論 |
| ⚠️ **裸 HP 加值** | 不平移**敵人**的階梯，但平移**玩家承傷**的階梯，並直接稀釋 T2 §4.3 的 MaxRegret 容錯模型。**列為黃燈：可用，但必須重算容錯次數** |

## 5.3 對「4 角色 × 2 定位 ＋ 2–3 個欄位」的具體建議 🟡

**建議的欄位語意**（借 FFT 的三格位結構，🔵 §3）：

| 欄位 | 語意 | 可放的東西 | 為什麼這樣切 |
|---|---|---|---|
| **① 動詞位** | 解鎖一個新指令 | 擊退／遲滯／嘲諷／破甲／反擊 | ΔVCI = +1，`S = 0`。**這是唯一會改變 `LegalCommands` 內容的欄位** |
| **② 觸及位** | 改變「碰得到誰／走得到哪」 | 射程 +1、MOVE +1、地形減免、推撞距離 +1 | ΔTCI > 0，`S = 0`。🟢 直接對應 [刀數模型 §10](NOTE-2026-08-14-敵人刀數與目標優先級數值模型.md)「接近成本是最強的旋鈕」 |
| **③ 規則位** | 改寫一條適用於自己的規則 | 免疫擊退／免疫遲滯／即死地形免疫 | ΔVCI = ΔTCI = 0 但改變**對手的**可用動詞 —— 這是唯一的「防禦型」格位，且不碰數值 |

> 🟡 **三個欄位沒有一個能放 ATK/DEF。這是刻意的，而且是本白皮書的核心主張。**
> 角色的強弱差異由 `units.txt` 的基礎數值決定（那裡有完整的設計理由與量測基準），
> **裝備只負責改變「能做什麼」。**

**⚠️ 「推撞距離 +1」有一個前置條件** 🟢：
`TryPushDestination`（`BattleSimulator.cs:515-528`）目前把推撞距離**硬編碼為 1 格**，
`PushRange` 是「能推多遠的目標」不是「推多遠」。
且 T3 §1.3 指出 R-TERR-07 的判定點是「**停下來的那一格**」——
**任何多格推撞都必須先回答「推過深坑算不算死」。** 在那之前這一項不可實作。

## 5.4 T5 會移動哪些數字 🟡

本檔以單一 AP 貨幣定價。若 T5 引入第二貨幣（TP／冷卻／耐力／單場次數）：

| 不受影響 | 會被推翻 |
|---|---|
| ✅ 綠燈/紅燈的**分類**（分類依據是 `S` 與 `ΔVCI`，與成本無關） | 🔴 §5.1 中「AP 上限 +1／回復 +1」一項 —— 它**本身就是 T5 的主題**，現在不要動 |
| ✅ §4.1 的 `S(b)` 表（純粹是傷害算術） | 🔴 被賦予動詞的**定價**：現行動詞出貨價是 1 AP，而 3 AP 已被量測否決（T1 §0④）。第二貨幣會讓「動詞應該多貴」重新開放 |
| ✅ §4.2 的 Juggernaut 餘裕表 | 🔴 T1 §4.6 的「動作數上限失控」若用第二貨幣收口，則**動詞位裝備的實際強度會下降**，紅燈清單不變但綠燈的強度排序會變 |
