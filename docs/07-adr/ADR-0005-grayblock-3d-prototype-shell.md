# ADR-0005 — Prototype 用 URP 3D 灰盒，維度／引擎路線延後

**Status**：`Accepted`
**Date**：2026-08-13
**來源**：專案負責人 2026-08-13 的指示

---

## Context

專案負責人的原話：

> 該專案目的是 Prototype，環境暫定 UDP 3D，之後要換 2D、2.5D、HD-2D
> 甚至換引擎都是等 Prototype 驗證玩法後再說。

同時 SPEC v0.1 §1.2 明確：**不做美術。灰盒方塊、純色、文字標籤。**

專案現況：Unity 6000.5.1f1 URP 範本，`Assets/` 只有範本檔案。

## Problem

「維度／引擎之後再說」聽起來像是**延後一個決定**，
但如果不處理，它會變成**一個永遠無法執行的延後**：

一旦規則邏輯散進 MonoBehaviour、格子座標用了 `Vector3`、
攻擊判定寫在 Collider 回呼裡 —— 換 2D 或換引擎就等於重寫整個專案。
到那時「再說」的答案永遠會是「不換，太貴了」。

**問題不是「現在用哪個維度」，而是「怎麼讓延後的決定真的還能執行」。**

## Options

### A. 現在就決定最終維度
違背負責人的指示，而且**在玩法未驗證前決定表現形式是本末倒置** ——
Prototype 的目的正是先驗證玩法。

### B. 做一層「維度抽象」，讓同一份表現層程式碼能跑 2D 與 3D
過度設計。跨維度的表現層抽象是很大的工程，
而且 HD-2D 與 3D 的差異遠不只是「少一個軸」。
**這是在為一個還不存在的需求付成本。**

### C. 承認表現層是可拋棄品，把成本花在讓「丟棄」變便宜

## Decision

**採 C。**

| 項目 | 決定 |
|---|---|
| Prototype 表現形式 | **URP 3D 灰盒**（方塊、純色、文字標籤） |
| 維度／引擎的最終決定 | **延後**，見 [OD-15](../OPEN-DECISIONS.md#od-15) |
| 表現層的地位 | **可拋棄品。換維度時整層重寫，不做跨維度抽象** |
| 規則層的地位 | **資產。換維度時一行不動** |

配套要求（**這才是本 ADR 的實質內容**）：

1. 規則層的空間概念用自訂 `Coord`（int X, Y），**不用 `Vector2` / `Vector3`**
2. 沒有任何規則邏輯放在 `MonoBehaviour` 裡
3. 沒有任何規則依賴 Unity 的物理、Collider、Raycast
4. 表現層只做三件事：播 EffectLog、顯示唯讀查詢結果、蒐集輸入
5. 以上由 [ADR-0001](ADR-0001-core-unity-assembly-split.md) 的
   asmdef **No Engine References** 編譯期強制

## Rationale

- **選 3D 而非 2D 沒有技術理由，是專案現況**（URP 範本已建好）。
  既然表現層是可拋棄品，**選哪個維度就不重要** —— 這正是本決策的重點
- **B 的抽象層會被浪費**：如果最後選 HD-2D，跨維度抽象幾乎沒有留下任何東西；
  如果換引擎，抽象層本身也要重寫
- **C 的成本已經因為 ADR-0001 付掉了**。本 ADR 幾乎是免費的 ——
  它只是把「表現層可拋棄」這件事寫下來，讓人不要往裡面塞規則
- 「灰盒」與「可拋棄」是同一件事的兩面：
  **不做美術**代表表現層的投資本來就很低，丟掉不心疼

## Consequences

### 正面
- 維度決定可以**真的**延後到玩法驗證之後，而不是被鎖死
- 表現層可以寫得很快很醜 —— 它的目的只是讓實驗跑起來
- 換引擎的成本 ≈ 重寫表現層，而不是重寫專案

### 負面 / 代價
- **3D 灰盒對「Exposure 一目瞭然」可能不是最好的呈現。**
  俯視 2D 通常更容易讀出格子關係。
  這會影響驗收問題 **Q2**（玩家會不會自己發現站進走廊）——
  如果 3D 視角讓玩家看不清楚格子，測到的可能是「視角很爛」而不是「設計無效」
  → 已登錄為 [OD-14](../OPEN-DECISIONS.md#od-14) 的一部分
- 表現層不做抽象 = 換維度時真的要重寫（**這是刻意接受的**）
- URP 3D 的初始設定（相機、光照、材質）有一點固定成本，
  對灰盒來說是浪費，但範本已經建好了

### 重新評估的觸發條件
- Prototype 驗證完成 → [OD-15](../OPEN-DECISIONS.md#od-15) 進入裁決
- 若 3D 視角被證實干擾 Exposure 的可讀性（Q2 的數據異常），
  可以在 Prototype 期間就改成俯視正交相機或直接換 2D ——
  **因為表現層是可拋棄品，這個改動很便宜。這正是本決策的價值。**
