# 0. 結論先講

### ① 本專案的「精確預告」成本近乎為零 —— 而且是所有戰棋裡罕見的

🟢 `EnemyAi.DecideNext(state, unit)` 是 **state 的純函式**：
R-AI-04 要求「同一個 state 永遠產生同一個 Command」，
[OD-16](OPEN-DECISIONS.md#od-16) 明確排除 Last Known Position / Fog of War / Patrol / Search State / **AI Memory**，
`IsActivated` 被降級為純觀測閂鎖（R-AI-05b：**不控制行為**）。

**敵方 AI 沒有任何隱藏狀態。** 所以在玩家按下結束回合的那一刻，
整個敵方階段**已經完全決定**，而且可以用 `Clone()` ＋ `RunFactionTurn` 直接跑出來。

> 🟡 **這代表 100% 精確預告不需要任何新的規則層狀態、不需要新欄位進 hash、A4 不動。**
> 對比 ITB：它必須把 Vek 的意圖**存進遊戲狀態**才能預告。本專案不必存，因為算得出來。
> **預告在這裡是純表現層功能。**

### ② 但「算得出來」和「該顯示」是兩件事 —— 真正的變數是**承諾（Commitment）**，不是顯示

🟡 這是本檔最重要的一節（§4.5）。ITB 的預告之所以能撐起整個戰術層，
**不是因為它顯示了意圖，是因為它把意圖凍結成事實**：Vek 在自己階段結束時提交意圖，
玩家整個階段內那些意圖**不會變**。

本專案的 AI 是**反應式**的。若照現況直接畫線：

```
玩家移動一格  ->  Hunter AI 重算最低 HP  ->  所有的線重畫
```

> 🔴 **在反應式 AI 上加意圖線，產生的不是決策，是搜尋。**
> 玩家會「試著動一動，看線變成什麼樣子」——這是 XCOM 1 overwatch creep 的資訊層版本。
> **意圖線的前提是意圖承諾。沒有承諾就不要畫線。**

### ③ 在確定性遊戲裡，隱藏資訊不是風險，是**作業**

🟡 有隨機命中的遊戲（FE / XCOM），隱藏結果會產生**真實的不確定性** —— 沒有人知道答案。
🟢 本專案 [OD-05](OPEN-DECISIONS.md#od-05) 確定性命中、AI 無隱藏狀態，
所以 `H(敵方行動 | 完整狀態 + 完整規則) = 0` —— **答案永遠存在且可算。**

> **所以本專案的資訊設計問題不是「該藏多少」，而是「該讓玩家做多少心算」。**
> 藏起來不會製造張力，只會製造勞動與「背 AI 規則」的記憶曲線。

### ④ 直接回答三個問題

| 問題 | 🟡 本檔的答案 |
|---|---|
| 需不需要意圖預測線？ | **需要，但不是現在。** 先做威脅圈（穩定、零規則成本），意圖線必須等意圖承諾一起做，否則是負收益（§5.2） |
| 純靠公開 AI 規則夠不夠？ | **解決了一半。** 公開規則讓 CF(目標) ≈ 1.0，但 CF(站位) 仍然低 —— 而站位決定了擊退、反擊射程、身體阻擋能不能用（§4.2） |
| 高致命下的容錯是多少？ | 🟢 **1.5 次。** Exposure 從 1 誤判成 3 = 200 傷 = 桃太郎 300 HP 的 67%（§4.3） |

| **敵人下一步打誰** | ❌ **完全不顯示** |

| **AI 的目標規則是什麼** | ❌ **完全不公開**（玩家只能反推） |

```

lowestHp     score = −候選.Hp
lowestDef    score = −候選.Def.Def
同分 -> unit id 較小者（R-AI-09）
嘲諷在半徑內時「絕對覆蓋」以上全部（EnemyAi.cs:182-187）
```

> 🟡 **三條規則、一個 tie-break、一個覆蓋。這是極小的資訊量。**
> 把它印在說明書上的成本是零，而它目前是完全隱藏的。

# 2. 核心衝突：預告買到的是前瞻深度，付出的是「AI 不能再聰明」

預告不是免費的資訊揭露，它是一個**架構承諾**：

> 一旦你告訴玩家「這隻會打桃太郎」，**AI 就再也不能改主意**，
> 否則預告變成謊言，而確定性遊戲裡的謊言比隨機性更傷。

所以預告的真正代價不在 UI，在 AI 的自由度：

| 你給的預告精度 | AI 從此不能做的事 |
|---|---|
| 威脅圈（哪些格會被攻擊） | 幾乎沒有限制 —— 威脅圈只依賴敵人的位置與移動力 |
| 目標預測（打誰） | 不能在玩家階段中途改目標 |
| 完整意圖（從哪一格、打誰、打多少） | 不能改站位、不能改目標、不能對玩家的行動做任何反應 |

> 🟡 **這是一條單調的取捨線，而本專案在線的左端有一個特殊優勢**：
> `SPEC-ai-behaviour §7` 明列「**MCTS / 多步推演：沒有需求**」——
> **本專案從來沒有打算讓 AI 變聰明。** 所以放棄 AI 自由度的代價，對這個專案接近零。

## 3.1 這張表的模式：預告精度追隨的是**隨機性**，不是難度 🟡

```
有隨機性  ->  隱藏資訊「便宜」，因為連 AI 自己都不知道結果 -> FE / XCOM 只給範圍
無隨機性  ->  隱藏資訊「昂貴」，因為答案存在而你不給     -> ITB / STS 給到 100%
```

> 🔴 **本專案目前是「ITB 的輸入條件 ＋ 聖火降魔錄的資訊政策」。**
> 這是表裡唯一一個沒有隨機性卻也沒有預告的格子。
>
> FE 的不透明可以被接受，是因為它**同時給了命中率** —— 它承認自己在賭，並把賭注量化給你。
> 拿掉隨機性之後再保留不透明，玩家得到的不是緊張感，是**「我算不出來，但電腦算得出來」**。

# 4. 數學模型

## 4.1 確定性遊戲的資訊論特殊性 🟡

令 `A` = 敵方階段的行動序列，`I` = 玩家握有的資訊。定義**確定性係數**：

```
CF  =  1 − H(A | I) / H(A)
```

| 遊戲類型 | `H(A｜完整狀態 ＋ 完整規則)` | CF 的上限 |
|---|---|---|
| 有命中骰（FE / XCOM） | **> 0**（不可約去的骰子熵） | **CF < 1，永遠達不到** |
| 🟢 **本專案**（OD-05 ＋ 無 AI 記憶） | **= 0** | **CF = 1 可達** |

> 🟡 **這是本專案與 FE/XCOM 的結構性差異，不是程度差異。**
> 在 FE 裡「不給完整資訊」是誠實的（給了也沒用）。
> 在本專案裡，任何 `CF < 1` 都是**刻意扣留一個可計算的答案**。
>
> 所以本檔不問「該給多少資訊」，改問：**每一份沒給的資訊，玩家要付多少心算？**

## 4.2 CF 分解：公開規則解決哪一半 🟡

玩家真正在乎的問題是「我這格會不會被打、被打多少」。它可以拆成兩個獨立的預測：

```
P(X 被 j 攻擊)  =  P(j 選 X 當目標)  ×  P(j 能移動到 X 的攻擊範圍內)
                    ↑ 目標選擇             ↑ 站位選擇
```

### 目標選擇：公開規則後心算負荷幾乎歸零 🟢

| 規則 | 玩家要算什麼 | 負荷 |
|---|---|---|
| `lowestDef` | 各玩家單位的 DEF —— **靜態，永不改變** | **O(1)**，第一回合算完就結束 |
| `lowestHp` | 各玩家單位的當前 HP —— **一次全域比較，對所有敵人同一答案** | **O(N_p)**，看一眼血條 |
| `nearest` | 各敵人到各玩家單位的格線距離，同分取 id 小者 | `O(N_e × N_p)` 次整數距離 |
| 嘲諷覆蓋 | 半徑內 → 目標 = 嘲諷者 | **O(1)**，且**把 CF 直接鎖成 1.0** |

> 🟡 **CF(目標) 在公開規則後 ≈ 1.0。全部是整數比較，沒有一項需要紙筆。**
> 🟢 而且 `lowestHp` / `lowestDef` 的答案**與敵人是誰無關** —— 全場敵人共用同一個答案。
> 這是一個被低估的性質：**兩條規則裡有兩條的預測成本與敵人數量無關。**

### 站位選擇：公開規則**解決不了** 🟢

🟢 評分公式（`EnemyAi.cs:245-263`）：

```
score  = −|pathDist(cell, target) − PreferredDistance| × 100
score −= StaticExposure(cell) × (100 − Aggression) / 10
score −= reach.CostTo(cell)
```

要預測，玩家必須：① 算出敵人的完整可達集合（含地形成本與單位佔位）→
② 對每一格跑一次到目標的**路徑距離**（Dijkstra，不是曼哈頓）→
③ 數每一格的 Exposure → ④ 加權求和 → ⑤ 取 argmax，同分取 `ReachableCells` 順序。

MOVE 3 的單位在開闊地約有 25 個可達格。**這不是心算得出來的東西。**

### 但有一個大幅簡化，值得寫進說明書 🟡

`aggression` 預設 70 → `survivalWeight = 30` → Exposure 項最大值 = `4 × 30 / 10 = 12`。
距離項的係數是 **100**。**距離項壓倒其餘兩項約 8–33 倍。**

> 🟡 所以站位規則在絕大多數情況下塌縮成一句話：
> **「移動到距離目標恰好 `PreferredDistance` 的、路徑最便宜的那一格。」**
> 近戰（`distance=1`）就是：**「能貼上就貼上，不能就盡量靠近。」**

**結論的精確形狀**：

| 玩家想預測的事 | 公開規則後的 CF | 誰需要它 |
|---|---|---|
| 我這回合**會不會**被打 | 🟢 **高** | 所有人 |
| **被誰**打 | 🟢 **高** | 所有人 |
| **從哪一格**打 | 🔴 **低**（Exposure/moveCost 的 tie-break 不可心算） | **擊退（推進深坑要知道站哪）、反擊（要在射程內）、身體阻擋** |

> 🔴 **這就是「公開規則夠不夠」的準確答案**：
> 對「我會死嗎」夠了；對**本專案的戰術動詞**不夠 ——
> 因為擊退、反擊、阻擋全部依賴「**從哪一格**」，而那正是唯一算不出來的那一項。

## 4.3 Max Regret：本專案的容錯是 1.5 次 🟢🟡

定義誤判的後悔值 `Regret(a) = V(a*) − V(a)`。以 HP 為單位，站位誤判的代價是：

```
MaxRegret(站錯一格)  =  ΔExposure × EDPT
```

🟢 帶入 Stage 01：小耗 ATK 100 vs 桃太郎 DEF 50 → 50 傷/刀 × 2 刀 = **EDPT 100**。

| Exposure | 每回合承傷 | 桃太郎（300 HP）撐幾回合 | 正守（435 HP、DEF 70 → 30 傷/刀）撐幾回合 |
|---|---|---|---|
| 1 | 100 | 3.0 | 7.25 |
| **2** | **200** | **1.5** | 3.6 |
| **3** | **300** | 🔴 **1.0（單回合陣亡）** | 2.4 |
| 4 | 400 | 0.75 | 1.8 |

```
從 Exposure 1 誤判成 Exposure 3  ->  MaxRegret = 200 HP = 桃太郎 67% 的血量
```

**容錯次數**：

```
k  =  MaxHP / MaxRegret  =  300 / 200  =  1.5 次誤判 / 場
```

> 🟢 這與 [playtest-metrics M4](06-validation/playtest-metrics.md)「熟練玩法應收斂到 Exposure 1–2」完全一致 ——
> M4 的 1–2 不是手感偏好，**它是致死線**：Exposure 3 就是單回合陣亡。
>
> 🟡 **而正守的容錯是桃太郎的 2.4 倍。** 這給了「誰站前面」一個資訊層的理由，
> 而不只是承傷層的：**正守是唯一能承受一次預測失誤的單位。**

## 4.4 需要預告的門檻不等式 🟡

```
需要精確預告  ⟺   MaxRegret / MaxHP   >   1 / k_可接受
```

`k_可接受` = 你希望玩家一場能犯幾次錯而不輸。

| 設計意圖 | 需要的 `MaxRegret / MaxHP` | 🟢 本專案實際值 | 判定 |
|---|---|---|---|
| 寬容（k = 5） | ≤ 0.20 | **0.67** | ❌ |
| 中等（k = 3） | ≤ 0.33 | **0.67** | ❌ |
| 硬派（k = 1.5） | ≤ 0.67 | **0.67** | ⚠️ 剛好在線上 |

> 🟡 **本專案落在「硬派」的邊界上，而且沒有給任何預告。**
> 這個組合在外部案例裡只有一個對應物：**沒有預告的 ITB**，而那個東西不存在。
>
> 兩條出路，二選一即可，**不必兩者都做**：
> **(a)** 給預告，維持高致命；　**(b)** 降低致命（例如降 EDPT），維持不透明。
> 🟢 但 [OD-20](OPEN-DECISIONS.md#od-20) 已經裁決**維持小耗 ATK 100**，理由是「根因是結構不是數值」。
> **(b) 已經被否決過一次，所以剩下的是 (a)。**

## 4.5 反應式 vs 承諾式：穩定性分析（本檔的核心） 🟡

定義**預告穩定性**：玩家在自己階段內做一個動作之後，先前顯示的預告有多少仍然成立。

| 顯示的東西 | 玩家移動後會不會變 | 為什麼 |
|---|---|---|
| **威脅圈**（哪些格這隻敵人打得到） | ✅ **幾乎不變** | 只依賴敵人自己的位置、MOVE、地形。玩家只有在**擋住路**時才改變它 |
| **目標線**（反應式，現況 AI） | 🔴 **每個動作都可能變** | `lowestHp` 在任何單位掉血時翻轉；`nearest` 在任何移動時翻轉 |
| **目標線**（承諾式，ITB 模型） | ✅ **完全不變** | 意圖在敵方階段結束時凍結，玩家階段內是常數 |

**反應式意圖線的失效模式** 🟡：

```
玩家想：「我把影丸移到這裡」
  -> 影丸 HP 195 < 桃太郎 300
  -> 所有 lowestHp 敵人瞬間改指影丸
  -> 玩家看到線全變了，退回去
  -> 再試另一格
  -> ...
```

> 🔴 **這是搜尋，不是決策。** 玩家在對 UI 做梯度下降。
> 它與 XCOM 1 的 overwatch creep 同構：**一個安全但無決策內容的最優程序。**
> 而且它比 overwatch creep 更糟，因為它連時間成本都沒有 —— 試探是免費且可無限次的。

**承諾式的三個副作用** 🟡（全部是好的，但都改變規則）：

| 副作用 | 內容 |
|---|---|
| **誘敵成為可能** | 承諾之後把目標移出射程 = 敵人的整個回合浪費。反應式 AI 下誘敵在定義上不可能 |
| **擊退獲得第二種價值** | 現在擊退只改變位置；承諾式下擊退還能**作廢一個已承諾的意圖**（ITB 的核心） |
| **嘲諷需要重新定義** | 🟢 `EnemyAi.cs:182-187` 的嘲諷是「絕對覆蓋」。承諾式下它要嘛**打斷承諾**（強力、易讀），要嘛**只影響下一次承諾**（慢一拍、可能太弱）。**這是一個必須裁決的分岔** |

> ⚠️ 意圖承諾**會動規則層**（AI 行為改變 → A4 golden hash 改變），
> 需要新的 state 欄位（承諾目標 / 承諾格）進 hash。**依 [documentation-rules](99-governance/documentation-rules.md) 應登錄 OD，本檔不裁決。**

# 5. 對本專案的具體指引

## 5.1 依「成本 → 效果」排序的四個檔位 🟡

| # | 做法 | 成本 | 買到什麼 | A4 |
|---|---|---|---|---|
| **I1** | **把三條 AI 目標規則公開**（說明書／教學／UI tooltip） | **零** —— 純文件 | CF(目標) ≈ 1.0（§4.2）。消除「背 AI 規則」的記憶曲線 | ✅ 不動 |
| **I2** | **威脅圈疊圖**：滑鼠停一格，顯示這格 Exposure ＋ 幾隻敵人打得到 | 低 —— 表現層 | 🟢 這是 [exposure.md](02-design/exposure.md)「UI 必須顯示」的既有要求，`OPEN → OD-14`。**穩定，不會因玩家動作亂跳**（§4.5） | ✅ 不動 |
| **I3** | **精確預告**：跑 `Clone()` ＋ `RunFactionTurn` 直接算出整個敵方階段並顯示 | 中 —— 表現層，**無新狀態**（§0①） | CF = 1.0 | ✅ 不動 |
| **I4** | **意圖承諾**：敵方階段結束時凍結意圖進 state，AI 必須履行 | 🔴 **高 —— 動規則層** | 誘敵、擊退作廢意圖、真正的 ITB 式謎題（§4.5） | 🔴 **會變，需 OD** |

> 🟡 **建議順序 I1 → I2 →（停下來量）→ I4 → I3。**
>
> **I3 排在 I4 之後不是筆誤。** §4.5 已論證：在反應式 AI 上顯示意圖線是負收益。
> **I3 的價值完全依賴 I4 先存在。** 先做 I3 會得到一個鼓勵玩家試探 UI 的介面。

## 5.2 直接回答「需不需要動態 UI 線」

> 🟡 **需要，但它是第四順位，不是第一順位。**
>
> 且它有一個**硬前置條件**：意圖承諾（I4）。
> 沒有 I4 的意圖線，畫出來的是一條會隨玩家每個動作重畫的線 ——
> 那不是預告，是**即時預覽**，而即時預覽的最優玩法是窮舉試探。

## 5.3 直接回答「純靠公開規則夠不夠」

> 🟡 **對「我會不會死」夠了；對本專案的戰術動詞不夠。**
>
> §4.2 的分解是精確的：公開規則把 CF(目標) 推到 ≈ 1.0，
> 但 CF(**從哪一格**) 仍然低 —— 而擊退（推進深坑）、反擊（攻擊者要在射程內）、
> 身體阻擋，**三個動詞全部只依賴那一項**。
>
> **所以 I1 是必做且免費的，但它單獨不足以支撐空間解謎。**
> 補足它的最便宜的東西是 I2（威脅圈），不是 I3。

## 5.4 一個被低估的既有資產：嘲諷是資訊工具 🟡

🟢 `EnemyAi.cs:182-187`：嘲諷在半徑內**絕對覆蓋**所有目標規則。

> 🟡 **這代表嘲諷不只是仇恨管理，它是全遊戲唯一能把 CF(目標) 直接鎖成 1.0 的動詞。**
> 玩家花 AP 買到的不只是「敵人打正守」，是「**我現在確定敵人要打誰**」。
>
> 在一個 MaxRegret = 67% HP 的遊戲裡，**買到確定性本身就是買到容錯**。
> 這條價值目前沒有被寫進任何文件，也很可能沒有被 [H16 技能豁免券檢核](NOTE-2026-08-16-H16-GDD技能豁免券檢核.md) 的量測捕捉到 ——
> 🟢 因為勝率量測不會區分「贏得輕鬆」與「贏得剛好」。

# 6. 順帶發現：目標選擇與站位選擇用了兩種距離 🟢

| 位置 | 用的距離 |
|---|---|
| `SelectPosition`（`EnemyAi.cs:233`） | `MovementCalculator.TerrainDistanceField` = **路徑距離**，繞得過牆 |
| `SelectTarget`（`EnemyAi.cs:205`） | `state.Map.Topology.Distance` = **格線距離**，**看不見牆** |

🟢 `EnemyAi.cs:230-232` 的註解說明了為什麼站位要用路徑距離：
「Manhattan cannot see walls, so on a map with a chokepoint both sides end up hugging
opposite faces of the same wall and the battle never resolves.」
—— 這是 [OD-18](OPEN-DECISIONS.md#od-18) 的修正。**但同一個修正沒有套用到目標選擇。**

> 🟡 **後果**：`nearest` 敵人會選一個「隔著牆很近」的目標，然後繞遠路過去；
> 同時忽略一個路徑上更近的目標。
>
> **對本檔的意義**：這正是玩家**不可能靠公開規則預測**的那類行為 ——
> 因為它連規則制定者都不是刻意的。要公開規則（I1），得先確定規則是想要的那條。
>
> ⚠️ 這是回報，不是提案。**是否統一成路徑距離屬於 [OD-18](OPEN-DECISIONS.md#od-18) 的範圍，本檔不裁決。**
> 🟢 另注意 OD-18 索引列已標 ✅ RESOLVED（2026-08-14，改用路徑距離），
> 但 `SelectTarget` 顯然不在該次修正範圍內 —— **裁決範圍與實作範圍可能有落差，值得確認。**
