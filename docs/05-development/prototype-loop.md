# 0. 三層：Engineering / Experimental / Gameplay

**這是整個迴圈的骨架，不是附錄。** 每一個出口的判別，最後都會歸到「這是第幾層的問題」。

| 層 | 問題 | 誰能回答 | 它守哪一關 |
|---|---|---|---|
| **1 Engineering correctness** | 系統做的事，跟規則說的一樣嗎？ | 測試、決定性、replay。**不需要判斷力** | 守**全部**。不成立時另兩層的結論一律作廢 |
| **2 Experimental validity** | 這次實驗真的量到它宣稱的東西了嗎？ | EP 前置檢查、只差一個變因的對照組、儀器限制清單 | 守 **Gym → Stage** |
| **3 Gameplay quality** | 玩起來有沒有產生有意義的決策？ | **只有真人在 Stage 上** | 守 **Freeze** 與 **Production** |

## 0.1 兩條防止層間污染的規則

> **規則 L1：第 2 層的結果永遠不能升格成第 3 層的結論。**
> 「腳本策略帶技能打得比較差」是關於**那個策略**的事實，不是關於**技能**的事實。

`[A]` 這個錯誤在本專案已經有六次同型前科 —— 反擊、淨化、控制技能、斬首、防禦、陣型，
全部是「機制有了、好的使用者沒有」。

`[A]` **做對的範例**：`shield-wall` 差 23–26 點，被記為「現有自動策略能力的**量測邊界**」而不是
「防守陣型不好」。**這是本規則的標準寫法。**

> **規則 L2：第 3 層的不滿，不能用第 1／2 層的工具修。**

`[A]` 已經發生過：用 round cap（跑分工具的安全網）去修「腳本策略不肯進砲塔射程」的僵持，
結果連帶壓平了所有需要時間的打法。

## 0.2 現成的層界標記：A4

`[A]` **「量測儀器的改動不應該讓 A4 失敗；如果失敗了，代表你不小心改到規則層。」**

這句話就是第 1 層與第 2 層的自動分界線，已經生效多次（技能／斬首擴充、D1 的動作分類都沒動到 A4）。
**沿用，不需要新增任何機制。**

# 2. A — Gym Exit Criteria

> **Gym 結束的條件不是「找到值」，是「再掃下去不會改變我要帶進 Stage 的那組候選」。**

## 2.1 六條結束條件

| # | 條件 | 為什麼是它 |
|---|---|---|
| **G1** | **失敗邊界的「形狀」已知** —— 懸崖、斜坡，還是非單調 | `[A]` 刀數 2→3 是 **68% → 1% 的懸崖**；地塊成本 2→3 是**非單調**（19% → 34%）。**候選站在懸崖邊和站在平原中間是兩件事**；哪個比較好只有 Stage 知道，但 Gym 有義務先講清楚站在哪 |
| **G2** | **候選彼此可分辨** —— 在 Gym 裡分不出來的兩個值，是一個候選 | `[A]` `corridor-hold` 有 ±5 的雜訊晃動。分不出來的兩個值不要各佔一次真人時間 |
| **G3** | **被支配的候選已剔除** —— 若 A 在 Gym 看得到的每個軸上都不如 B，A 只有在寫得出「為什麼它在 Stage 可能反而好」時才留下 | 那個理由會直接變成 Stage 的觀察項 |
| **G4** | **主變數已識別** | `[A]` 「凡是改『敵人幾回合後打得到你』的旋鈕效果都很大」→ **release time 是主變數**。不知道主變數，Stage 的回饋無法歸因 |
| **G5** | **只差一個變因的對照組存在** | `[A]` Playbook §0 唯一一條無法用更多場次補救的紀律 |
| **G6** | **儀器限制已寫下，且沒有任何一條吃掉主結論** | 見 §2.2 |

## 2.2 🔴 什麼情況**還不能**進 Stage

| 情況 | 判別方式 | 正確動作 |
|---|---|---|
| **主結論可被儀器限制解釋** | 問：「換一個策略／clock／雜訊設定，這個結論還在嗎？」答不出來就是還在 | 修儀器或改問法。**不是進 Stage** |
| **一次動了兩個變因** | `[A]` OD-31 自己記過：「敵人 8→6 ＋ 加 20 回合上限」同時動 | 補中間那張對照圖 |
| **候選集是空的，或等於整個空間** | 前者代表設計沒放東西進去；後者代表沒學到東西 | 回設計 |
| **EP 說這張圖沒東西可說** | `[A]` residue 全為 0 ⇒ 集火是唯一解；lethal exposure ≤ 2 ⇒ 一次失誤就死 | 改 encounter，別跑 |

## 2.3 🔴 例外：有些變數不該為了取得 candidate range 而強行掃描

> **[OD-33](../OPEN-DECISIONS.md#od-33) 裁決：**
> **凡是核心問題依賴真人才能產生的變數，不應為了取得 candidate range 而強行掃描 Gym。**

**判別問句**：這個變數的價值，取決於**一個腳本能複製的東西**，還是取決於**一個只有人會做的判斷**？

`[C]` 已知會落進這一類的形態（**這是例示，不是封閉清單**）：

| 形態 | 為什麼腳本產不出候選 |
|---|---|
| **時機判斷**（何時放技能／何時撤退／何時留 AP） | `[A]` 腳本策略評不了「什麼時候該放」 |
| **接觸時機的選擇**（要不要進射程） | `[A]` 腳本策略不會為了打不動的敵人前進 → 無 clock 時 **33% 僵持** |
| **設計語言的選擇**（硬性剋制 vs 軟性分工） | `[A]` 減法 vs 百分比勝率只差 8 點，但「帶錯隊伍打不動 vs 只是比較慢」不是勝率問題 |
| **風險偏好**（穩健推進 vs 搶節奏） | 腳本沒有偏好，只有評分函數 |
| **可讀性**（盤面看不看得出來） | 腳本讀的是狀態不是畫面 |

**落進這一類時，Gym 的正確產出是**：

1. 仍然做**尺度、失敗邊界、儀器限制**三欄（這些不依賴人）
2. **候選值那一欄留白，標記 `Stage-only`**
3. 直接進 Stage

`[A]` **這條規則的第一筆帳**：技能 AP 成本掃描（1/2/3/4/5 五檔、六個策略）
在第一格就該停 —— 它替一個「使用者不存在」的東西定價。

> ⚠️ **不要反過來濫用這條。**
> 同一個機制常常同時有 gym 答得了與答不了的子問題。
> `[A]` 例：「遲滯有沒有延後接觸」**是** gym 問題（答案是沒有：release 2.50 → 2.51，248 次遲滯）；
> 「遲滯值不值 1 AP」**不是**。**先把問題拆到這個粒度，再判斷它屬於哪一邊。**

# 3. B — Stage Entry Criteria

> **Stage 的稀缺資源是專案負責人的注意力，不是機器時間。**
> `[A]` 目前真人 playtest 的累積總量是**一句話**。以下每一條都是為了保護這件事。

| # | 條件 | 判別問句 |
|---|---|---|
| **S1** | **候選少到能在一次坐下來的時間內感覺出差別** | 「我今天能不能把這幾個都玩過？」不能 → 先砍 |
| **S2** | **有一個用「話」講出來的預期決策變化** | 「AP 收緊後我應該會**被迫放棄某個動作**」← 可憑感覺驗證<br>「AP 6 比較好」← 不能，退回重寫 |
| **S3** | **Stage 的結構真的承載得住那個變因** | `[A]` 「移動 1 ＋ 攻擊 ＋ 防禦 = 恰好 8 AP」的局面**測不了 AP**；`[A]` `test_turret`（MOVE 0）是唯一把「要不要接近」還給玩家的原型 —— **沒有那個結構，那個決策就不存在** |
| **S4** | **一個 Stage 只扛一個主要 decision context** | `[A]` E1–E4 的檔頭已有 `PRIMARY PRESSURE` / `SECONDARY` / `ALTERNATIVE SOLUTION` 三欄。**沿用這個格式** |
| **S5** | **Engineering correctness 是綠的** | 測試全過、A4 狀態有交代、replay 決定性可用。否則會把 bug 讀成設計問題 |
| **S6** | **Stage 被設計成專門回答 Gym 答不了的那幾條** | 直接拿 Candidate Record 的「Gym 看不到的」那一欄當設計輸入 |

## 3.1 兩件反直覺但重要的事

**① Gym「答不了」是有效的入場券。** §2.3 那一類**只能**這樣進 Stage。

**② 不要為了進 Stage 而先把 Gym 數字調好看。**
`[A]` Playbook §9.8 已記兩次前科。上面六條全部是**結構性**的，沒有一條要求勝率達標 —— 這是刻意的。

# 4. C — Stage Playtest（觀察框架，不是門檻）

> **[OD-33](../OPEN-DECISIONS.md#od-33) 裁決：先記錄，暫不評分。**
> 這一節產出的是「發生了什麼」的紀錄，不是「好不好」的評分。
> 判斷基準要從累積的 Stage Log 長出來 —— **不要急著建立新的分數門檻。**

## 4.1 🔴 證據等級（**這一節比觀察項本身重要**）

**Prototype 的目標不是「每回合有幾個選項」。** 四類觀察的地位並不相同：

| 觀察 | 地位 | 意思 |
|---|---|---|
| **同一 action 的價值隨 context 改變** | 🔴 **核心研究命題** | Prototype 最終要驗的就是這個 |
| **Trade-off（被迫取捨）** | 🔴 **核心 gameplay evidence** | 「必須在互相衝突的目標之間選」的直接證據 |
| **Dominant action** | **診斷訊號** | 出現代表某處塌陷，指出要往哪裡查 |
| **決策數量** | **觀察素材** | 只是原料。**數量多不等於好** |

> ⚠️ **不要把「每回合選項變多」當成進展。**
> `[A]` 反例：AP 從 4 加到 12，動作組合種類 8→12→27→32→44→52 平滑上升，
> 而勝率完全不是那個形狀。**兩者要分開看。**

## 4.2 七個觀察軸

**優先記錄前四項**（[OD-33](../OPEN-DECISIONS.md#od-33) 指定）：發生了什麼、我做了什麼選擇、為什麼、放棄了什麼。

| 軸 | 記什麼（**不是評分，是記錄**） | 壞掉時的樣子 |
|---|---|---|
| 🔴 **① 同一 action 的不同理由** | **這次做這個動作的理由**。移動：為了接近？為了脫離射線？為了讓出格子？ | **理由永遠一樣** → 這個 action 的價值不隨局面改變 |
| 🔴 **② 放棄了什麼** | 這回合**想做但沒做成的事，以及拿什麼換的** | 整場空白 → 預算太寬（`[A]` 這正是「一回合塞得下全部」目前預測的結果） |
| **③ 沒有猶豫的回合** | 哪幾回合**在看盤面之前就知道要幹嘛** | `[A]` playtest-guide Q6 已經是這一條 |
| **④ 決策數量／種類** | 每回合**認真比較過幾個選項**（不是合法選項有幾個） | 長期只有 1 個 |
| **⑤ 三種不同的壞（分開記，修法完全不同）** | **無意義等待** = 盤面還沒開始問問題（節奏／release time）<br>**無解** = 一次失誤就死，或這個目標根本處理不了（`[A]` 減法下正守打 DEF 45 = 保底 1 傷 = 120 刀）<br>**顯然唯一答案** = 決策空間塌陷 | 混在一起記 → 下一步一定修錯地方 |
| **⑥ 這張 Stage 有沒有測到它想測的** | **我建它是為了測 X，X 這回真的出現了嗎？** | `[A]` 例：rout 目標下 **175/200 場從未踏上分隔牆那一列** —— 那張圖的路線實驗其實沒跑到 |
| **⑦ 想做但系統不讓** | 原話記下來 | 可能是規則缺口，也可能是缺一個決策維度 |

## 4.3 三條程序紀律（比觀察項更容易被破壞）

| # | 紀律 | 為什麼 |
|---|---|---|
| **P1** | **A/B 在同一次坐下來完成** | `[A]` playtest-guide 已寫：「最有價值的一次試玩是 `-` 跟 `=` 各打一場」。隔天玩會混進手感成長 |
| **P2** | 🔴 **記錄寫完之前，不要看那張圖的自動化數字** | `[A]` 目前 [playtest-guide §7](../06-validation/playtest-guide.md) 把勝率印在同一份文件裡給玩的人看。**這會把量測變成確認** |
| **P3** | **記「發生了什麼」，不記「幾分」** | 評分需要還沒有的基準；記錄不需要 |

# 5. D — Stage Exit Criteria

> **四個出口的差別在「歸因到哪一層」，不在「玩得爽不爽」。**
> 這一節主要防的是一個很自然的失敗：**每次都結論成「回 Gym 調數值」。**

## 5.1 判別順序（第一個中的就是出口）

```
Q0  這是 bug 嗎？（規則做的事和規格不一樣？）
      是 → 修 code，重跑。⚠️ 不產生任何設計結論
      ↓ 否
Q1  我想測的東西這回出現了嗎？（§4.2 ⑥）
      沒出現 → ► 修改 Stage        ⚠️ 不要碰數值
      ↓ 出現了
Q2  問題能歸因到那個變因，而且我說得出方向嗎？
      不能 → ► 修改 Stage 或換 context（先排除是關卡的錯）
      能   → ► 回 Gym，帶一個更窄的問題（不是重掃）
      ↓ 沒有問題
Q3  這個候選只在這一種 decision context 裡驗過嗎？
      是 → ► 保留 candidate，換一個 context 再玩
      ↓ 否，跨不同 context 都活著
                    ► 暫時 Freeze（見 §5.3）
```

## 5.2 四個出口各自的紀律

| 出口 | 做什麼 | 🔴 不要做什麼 |
|---|---|---|
| **修改 Stage** | 改地形／敵人配置／目標，讓那個變因真的被行使 | **不要同時改數值**，否則下一輪分不清是誰造成的 |
| **回 Gym** | 帶一個**更窄**的問題：「是 AP 太低，還是移動成本太高，還是射程太短？」 | **不要重掃原範圍。不要預設是哪個變因** |
| **保留 candidate** | 換 decision context 再玩，把 Stage Log 附在候選紀錄後面 | 不要因為「這次還行」就 freeze |
| **暫時 Freeze** | 見 §5.3 | 不要寫進 SPEC 的 `STABLE`、不要寫進 GDD |

> **硬規則**：「玩起來不好玩」**本身不是回 Gym 的理由**。
> 必須先說出**缺了哪一個決策**（用 §4.2 的軸講）。
> 說不出來 → 那是 Stage 設計問題或觀察不足，不是數值問題。

## 5.3 Freeze 的條件

> **[OD-33](../OPEN-DECISIONS.md#od-33) 裁決：**
> **Freeze 必須建立在跨不同 decision context 的 Stage evidence 上；
> 具體需要多少個 context 暫不固定，待實驗累積後形成。**

`[C]` 所以 Freeze 的判別是**質性的**，不是數個數：

- 這些 context 是**不同類型**的，不是同一種情境的變體
- 在這些 context 裡，**沒有出現想改它的理由**
- 而且**說得出它為什麼沒被推翻**（不是「沒人抱怨」）

`[A]` **目前的文件體系沒有「暫時」這個詞** —— OPEN-DECISIONS 只有 OPEN / DECIDED，
而 workflows §5 的裁決流程是把 SPEC 的 Status 改成 `STABLE`。
**因此 Freeze 一律用 §7.3 的格式記錄，不做狀態轉換，不進 SPEC。**

# 6. E — Prototype-Level Exit

> **判準不是「所有數值都定了」，而是「我對這套玩法的判斷力已經足以下注」。**

## 6.1 六個正面訊號

| # | 訊號 | 為什麼它是訊號而不是感覺 |
|---|---|---|
| **E1** | 🔴 **能預測自己的體驗** —— 玩一張沒玩過的 Stage 之前說得出哪裡會難，而且大致說中 | 直接證明已經建立了原本沒有的那套判斷。**這是唯一能證明「Prototype 完成了它的職責」的訊號** |
| **E2** | **同一個 action 的價值確實隨 context 改變** —— 由真人跨多個 Stage 觀察到，不是從指標推論 | 核心研究命題 |
| **E3** | **不同 decision context 產生了不同的玩法**，不是同一套玩法配更多敵人 | |
| **E4** | **4 個角色（×2 定位）覆蓋到不同的策略地面** —— 是不同的**答案**，不是不同的數值表 | `[A]` E1–E4 的 A/B 變體已是這個實驗的雛形 |
| **E5** | **發現的問題都能用這套設計自己的詞彙修** —— 說得出是哪個旋鈕 | 每個問題都要新增一個系統，代表核心還沒立起來 |
| **E6** | **存在至少一次講得出來、可重現的「好決策」體驗** | `[A]` 目前這一欄的全部內容是：「移動到小怪 4 格附近等他靠近，接著下回合兩刀劈死。保留跟不保留都差不多。」 |

## 6.2 三個反面訊號

| 訊號 | 意思 |
|---|---|
| **每次改善都要靠加系統** | 決策深度不是底層長出來的，是內容堆出來的 —— 在 Production 會無限膨脹 |
| **只有知道數字的人玩起來才有意思** | 決策沒有從盤面上讀得出來 |
| **`[A]` 六次「機制有了、好的使用者沒有」，而真人也複製了同一個結果** | 若真人也用不出來，那才**第一次**成為 gameplay 結論。**在真人試過之前，這一條不能算數** |

## 6.3 一句誠實話

**這一層，專案負責人的主觀判斷就是儀器，這是正確的。**
本迴圈能做的只有一件事：讓那個判斷建立在**累積的 Stage Log** 上，
而不是建立在某一次的手感或某一列勝率上。

# 7. 三種紀錄格式

## 7.1 Candidate Record

登錄在 [candidate-records.md](../06-validation/candidate-records.md)。

```
變因：            <名稱>，尺度 = <單位>        ← 必填，防止尺度錯置
候選值：          <值1> / <值2> / …            ← §2.3 的類型此欄留白，標記 Stage-only
各自為何存活：    <一行>
失敗邊界：        下緣 <值> ／ 上緣 <值> ／ 形狀：懸崖 / 斜坡 / 非單調
主變數與交互作用： <這個變因和誰一起動才有意義>
🔴 Stage 預測：   若採 <值1>，我預期在 Stage 看到 <具體可觀察的事>
                  沒看到 → 回 Gym（帶著這個問題，不是重掃）
儀器限制：        <綁著這個結果的條件：策略／clock／noise／objective／map>
Gym 看不到的：    <明確列出。這一欄直接變成 Stage 的觀察清單>
```

> **「Stage 預測」是讓迴圈可以閉合的那一欄。**
> `[A]` Playbook §1 第 1 步已要求對 **Gym 結果**做預測（「事後才寫下來就不算預測了」）。
> 同一條紀律套到 Stage，就是這一欄。

> **「尺度」那一欄不是形式**：`[A]` 本專案的 AP 尺度是**每回合恢復 8、上限 10、攻擊 4**。
> 用別的尺度討論 AP 會直接產生一次錯誤實驗。

## 7.2 Stage Log

`[C]` 沿用 [playtest-guide §5](../06-validation/playtest-guide.md) 的表，補三欄：

```
Stage / candidate：  <哪張圖、用哪個候選值>
這張圖想測的是：      <一句話，玩之前寫>
Gym 的預測是：        <抄 Candidate Record 的 Stage 預測欄，玩之前寫>
────────── 以上玩之前寫完，以下玩之後寫 ──────────
① 同一 action 的不同理由： 移動 → r__:____　r__:____　r__:____
② 放棄了什麼：            r__ 我想 ____，因為 ____ 只好放棄
③ 沒猶豫的回合：          r__ ~ r__
④ 認真比較過的選項數：     大致 __ 個／回合（印象即可）
⑤ 壞的種類：             無意義等待 / 無解 / 唯一答案（圈選 ＋ 哪幾回合）
⑥ 想測的東西出現了嗎：     有 / 沒有（沒有的話：為什麼沒出現）
⑦ 想做但系統不讓：         
預測 vs 實際：            符合 / 不符合（不符合的地方：____）
```

## 7.3 Freeze Record

```
變因與值：         <值>，尺度 = <單位>
跨過哪些 context： <列出類型，不是數量>
每個 context 觀察到的： <一行>
🔴 解凍條件：      「當 <X> 改變時，本 freeze 自動失效」
                  （例：AP 預算改變、ZOC 進來、敵人 AI 改打法）
本 freeze 不涵蓋： <還沒驗過的情境>
效力範圍：         Prototype only。**對 Production 無約束力**
```

> **只在一種 context 驗過的值不叫 freeze，叫「還沒被推翻」。**
