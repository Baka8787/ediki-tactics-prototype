## 0. 一句話

> **一次只動一個變因，而且每個實驗組都要有一個「只差那一個變因」的對照組。**

這條紀律是本專案唯一無法用更多場次補救的東西。
200 場跑錯設計，得到的是 200 場的錯結論。

# 1. 一次實驗的六個步驟

```
0  開工前檢查（workflows.md §0）
       OPEN-DECISIONS 有沒有擋著？CONFLICTS 有沒有相關？
       charter §4 非目標清單裡有沒有？找不到 R-xxx？
       → 任何一項中了就停，登錄，不要自己決定

1  寫下這次要問的問題，以及「什麼結果會推翻它」
       寫在 encounter 檔的檔頭註解裡，不是寫在腦子裡
       ⚠️ 預測被推翻過至少兩次（§10.5 的 arena-stagger、§16.4 的弱目標）
          —— 事後才寫下來就不算預測了

2  先算衍生指標（EP），再決定要不要跑
       跑分工具的 `profile` 模式，不跑任何一場戰鬥
       EP 說「這張圖沒東西可說」的話，跑 1000 場也不會有

3  建資料檔：一個實驗組 ＋ 一個只差一個變因的對照組
       實驗組與 baseline 差兩件事的話，數字歸誰造成的分不出來
       → §16 的斬首實驗每張 `-kill` 都配一張同組成的 rout 對照

4  跑分：200 場/格、base seed 1、noise 15%、round cap 60
       Unity 選單 Ediki > Run Metrics，或 Unity 外同一份程式碼

5  依 §3 的順序讀數字，把結論寫進 playtest-metrics.md
       ⚠️ 連同「這一輪的儀器限制」一起寫，不要等下一輪才發現
```

## 1.1 什麼時候需要動程式

| 你要做的 | 要不要寫程式 |
|---|---|
| 換數值、換地形、換敵人組成、換 spawn 位置 | **不用**。全部是資料 |
| 新的敵人原型（只由現有欄位組成） | **不用**。加一行 `units.txt` |
| 新的勝利條件 | 要。走 [workflows.md §3](workflows.md)，會動到 `R-WIN-*` |
| 新的策略（量測儀器） | 要，但只動 `Ediki.Sim`，**不碰規則層** |
| 新的動作（治療、位移…） | 要，動 `Ediki.Core`。**先登錄 OD** |

> **新增單位不應該需要寫程式。** 需要就代表資料驅動沒做好（違反測試 A5）。

# 2. 對照組怎麼設計（最容易做錯的一步）

一張新場地相對 baseline 通常差了**不只一件事**。每差一件，就要多一張圖。

以本輪的斬首實驗為例，`gym-big-split-boss4-kill` 相對 `gym-big-split` 差了兩件事
（敵人組成、勝利條件），所以中間必須有一張只差組成的：

| 場地 | 組成 | 目標 | 用來減什麼 |
|---|---|---|---|
| `gym-big-split` | 4× kohaku | rout | baseline |
| `gym-big-split-boss4` | 3× kohaku ＋ 1× 4 刀 | rout | **組成的價格** |
| `gym-big-split-boss4-kill` | 同上 | kill | **目標的價格** |

**策略也是變因，而且是同一套邏輯。** `tpa-order` / `residue-aware` / `decapitate`
全部繼承 `corridor-hold` 且**只覆寫 `ChooseTarget`**，
所以每一個減掉 `corridor-hold` 就是那一條目標規則的價格 —— 站位邏輯一個字都沒改。

> **儀器接對了線的最便宜證明**：在那條規則不可能生效的地圖上，
> 子類必須與父類**逐位元相同**。三個策略各有一條這樣的測試。

# 3. 跑完看哪些指標（**有順序**）

**先看免費的，再看貴的。前面的決定後面有沒有東西可說。**

## 3.1 第一層 — EP（衍生指標，不跑戰鬥）

從 `units.txt` ＋ 地圖直接算，印在每張圖跑分報告的最前面。

| 欄位 | 定義 | 怎麼讀 |
|---|---|---|
| `lethal exposure` | `ceil(玩家HP / 敵人每回合傷害)` | **≤ 2 = 一次失誤就死**，其他問題都在這個下游 |
| `hits`（刀數） | `ceil(敵HP / 玩家每刀傷害)` | 見 §5.3 的懸崖 |
| `dmg/turn` | 敵人一回合打出的傷害 | |
| `TPA` | `dmg/turn ÷ 刀數` | 純傷害競賽下的最佳擊殺順序 |
| `residue` | `刀數 mod 玩家每回合攻擊次數` | **全為 0 ⇒ 集火是唯一解**，沒有零頭行動可分配 |
| `approach AP` | 玩家走到打得到它的位置要幾 AP | 在 OD-16 下這是 release time，不是成本 |

> **EP 說「所有 residue 都是 0」的場地，不管跑幾百場，
> M1 都不會告訴你「玩家在分配行動」。** 那不是量測失敗，是設計沒放東西進去。

## 3.2 第二層 — M7 / M5（結構有沒有成立）

| 指標 | 看什麼 | 門檻 |
|---|---|---|
| **M7 回合 1 接觸數** | 開場就有幾隻打得到你 | **= 全部 ⇒ 空間層失效**，這張圖退化成排序問題 |
| **M5 勝率落差** | 守勢 − 衝鋒 | 兩者接近 ⇒ **地圖沒教到東西** |

M5 的目標是守廊 > 80%、衝鋒 < 20%。目前的落差紀錄：

| 場地 | 落差 |
|---|---|
| `gym-turret`（固守敵人） | **65** |
| `gym-big-split` | 49 |
| `gym-lanes` | 23 |

## 3.3 第三層 — M4 / M6（主命題與地圖）

| 指標 | 定義 | 門檻 |
|---|---|---|
| **M4** | 回合結束時的 Exposure 分布 | 熟練玩法應收斂到 1–2。**若與勝負無相關，核心命題失敗** |
| **M6** | 玩家第一次踏上探針列時的 x 分布 | 三條都在 20–45%；最常用 > 70% ⇒ 路線選擇是假的；某條 < 5% ⇒ 死路線 |

**M4 是最重要的一條** —— 其他都在測手感，M4 能證偽主假說。

## 3.4 第四層 — M1 / M1b / M2 / M3（手感）

| 指標 | 目標 | 觸發改設計 |
|---|---|---|
| **M1** 同一動作組合佔比 | < 70% | ≥ 70% ⇒ 決策空間塌陷，調 AP 成本 |
| **M1b** 同上但**每單位**計 | < 70% | **跨隊伍人數比較只能用這個** |
| **M2** 殘 AP 浪費率 | < 15% | 持續 > 25% ⇒ AP 粒度或成本錯了 |
| **M3** 平均回合數 | 6–10 | < 4 太短、> 15 拖沓 |

## 3.5 第五層 — 求解器（要不要跑要自己決定）

`Sim/PositionSolver.cs`。列舉某單位的每個合法指令，各自推演到 horizon 打分。

| 輸出 | 意思 |
|---|---|
| **Spread** | 最差 ÷ 最佳。**1.00 = 這個局面沒有決策** |
| **NOAR(5%)** | 落在最佳解 5% 內的行動比例 |
| 四象限 | NOAR 小＋Spread 大 = 唯一解；**NOAR 大＋Spread 大 = 真決策**；NOAR 大＋Spread≈1 = 無關緊要 |

十張圖只有 `arena-conflict` 與 `gym-big-split` 落在「真決策」象限。

> ⚠️ **求解器是單步前瞻 ＋ 策略推演，不是完整博弈樹。**
> 數字的意思是「假設後續由 `corridor-hold` 接手」。換一個推演策略，所有數字都會變。
> 而且目標函數是**選的不是推導的** —— 這正是 F04 要驗的東西。

# 4. 地形與地圖配置

## 4.1 現有地形（`terrain.txt` 全部）

| 符號 | 名稱 | 進入成本 | 阻擋 |
|---|---|---|---|
| `.` | Road 道路 | 1 | |
| `o` | Open 開闊 | 1 | |
| `f` | Forest 森林 | 2 | |
| `^` | Highland 高地 | 2 | |
| `m` | Mire 泥沼 | **3** | gym 專用 |
| `#` | Blocking 阻擋 | — | ✅ |

`cost` 可以是小數（`cost=1.5`），**累積後只進位一次**（走 2 格森林 = 3 AP 不是 4）。
內部存百分之一 AP 的整數，規則層看不到浮點數。

> **成本 3 與成本 2 是不同「種類」的地形，不是同一種地形換價錢。**
> 一回合 AP 預算是 8：森林 2 走得起，泥沼 3 走不起。
> 而且它**非單調** —— 成本 2 → 3 讓勝率 19% → **34%**，因為它開始保護玩家：
> 玩家可以選擇不過去，而敵人（OD-16）非過來不可。

## 4.2 地圖語法

```
map
##################
#................#
###.###..###.#####     <- 分隔牆，缺口在 x=3 / x=7,8 / x=12
#................#
##################
endmap
```

- 每一列長度必須相同
- 座標是 `(x, y)`，**y = 0 在最上面**
- 符號必須在 `terrain.txt` 宣告過
- 載入時會驗證**連通性**：玩家走不到的敵人 = 直接拒絕（R-MAP-02）

## 4.3 幾何設計的四條經驗

| 經驗 | 出處 |
|---|---|
| **「看起來有三條路」不等於有三條路** | `gym-big-split` 的中路缺口只開 4 格、可達敵人 0 隻 —— 是死巷不是路線。**M6 是唯一能證偽這件事的指標** |
| **三條路的成本要接近，差別要在暴露度與地形** | `gym-big-split` 的中路正在玩家頭上，「走哪條」是算術題。`gym-lanes` 加了一塊阻擋把三條拉到 ~11/~14/~14 |
| **路線寬度 × 隊伍人數會互相作用** | 加一個正守之後中路佔比 43% → 71%，合理解釋是西路只有 1 格寬、兩個單位過不去 |
| **有洞可以躲會膨脹 M5 落差** | `corridor-hold` 在 `gym-big-north` 有 93% 的「穿越」是躲進全圖 Exposure 最低的洞。那 49 點裡有一部分是洞給的 |

## 4.4 探針列（M6 用）

分隔牆在哪一列，就把那個 y 填進 `SimulationMenu.AddMap` 的第三個參數。
**沒有分隔牆的地圖填 `-1`** —— 沒有路線可數，填了會產生「關於無」的數字。

`gym-big-split` = 5、`gym-lanes` = 8、`gym-opening` = 4、**D1 三張圖 = 5**、開放競技場 = -1。
斬首變體**沿用基礎圖的探針列**，否則直方圖不能跟基礎圖比。

> ⚠️ **M6 的百分比只算「有穿越的場次」，是條件分布。**
> D1 三張圖的穿越率是 99 / 63 / 100（每張 200 場），
> **穿越率差 18 點就等於分母換了一群場次** ——
> 兩張穿越率差很多的圖，M6 直方圖不能直接相減
> （[playtest-metrics §22.6](../06-validation/playtest-metrics.md)）。

# 5. 敵我數值配置

## 5.1 `units.txt` 的欄位

```
unit id= name= hp= atk= def= move= ap= [apRegen=] range= attackCost= guardCost=
     [counterCost=] [restCost=] [restHealPercent=] [atkGrowth=]
     [purifyCost=] [purifyRadius=] [contaminates=] [contaminateRadius=]
```

| 欄位 | 意思 | 目前基線 |
|---|---|---|
| `ap` | AP **上限**。沒花完的會保留到這個值 | 10 |
| `apRegen` | 每回合phase 開始時補的量（加在保留的上面） | 8 |
| `move` | **一回合**最多走幾格（不是一次移動） | 桃太郎 4 |
| `attackCost` / `guardCost` | 4 / 3 | |
| `restCost` / `restHealPercent` | 休息：便宜、回一點血、**然後結束這個單位的回合** | 2 / 10% |
| `counterCost` | 被攻擊時**必須還沒花掉**的 AP，換一次反擊。0 = 不反擊 | 0 |
| `atkGrowth` | 每過一回合 ATK +N。**從回合數推導，不存狀態** | 0 |

**傷害公式**：`max(1, ATK − DEF)`，確定性，無命中骰（OD-05）。
`rules damage=percent` 可以逐 encounter 換成百分比減傷（OD-27 待裁決）。

## 5.3 敵我數量與「已經量過的旋鈕」

Stage 01 基線是**桃太郎 ×1 vs 小耗 ×4**（GDD ＋ SPEC 一致）。
實驗場多半沿用，因為改人數會同時改掉太多東西。

已量過的六個變因（完整見 [§11](../06-validation/playtest-metrics.md)）：

| 變因 | 幅度 | 性質 |
|---|---|---|
| 射程差 +1 | 19% → 70% | **全專案最強的單一旋鈕** |
| 站位（固守敵人） | 落差 65 | 最大的策略落差 |
| **目標優先級（斬首目標下）** | **+25** | 見 §16 |
| 刀數 2 → 3 | 68% → 1% | **懸崖，不是斜坡** |
| 成長率 0 → 20 | 90% → 13% | 反龜縮，不需要回合上限 |
| 地塊成本 2 → 3 | 19% → **34%** | **非單調 —— 反而變好過** |
| 目標優先級（全滅目標下） | 0–5 | 幾乎不值錢 |

> **凡是改「敵人幾回合後打得到你」的旋鈕（射程、地塊成本、成長率）效果都很大；
> 凡是只改「打死它要幾下」的旋鈕效果都很小或是懸崖。**
> release time 是主變數。

# 6. encounter 檔完整語法

```
# 註解。這裡要寫「這張圖為什麼存在」與「預測是什麼」

encounter id=<唯一 id> name=<顯示名>
objective type=rout|reach|survive|defend|kill [x= y=] [turns=]
rules damage=subtractive|percent          # 省略 = subtractive

map
...
endmap

spawn faction=player|enemy unit=<id> x= y= [ai=<profile>] [turn=N]
      [protect=true] [target=true] [group=<name>]
```

| 目標 | 勝利條件 | 時限 |
|---|---|---|
| `rout` | 全滅敵人 | 選用 |
| `reach` | 站上 `(x,y)` | 選用 |
| `survive` | 撐過 N 回合 | **必填** |
| `defend` | `protect=true` 的單位撐過 N 回合 | **必填** |
| `kill` | 殺掉 `target=true` 的那隻，其餘可留 | 選用 |

**清空戰場在任何目標下都算贏**，所以 rout 永遠是可行解。

三個 AI profile（`ai-profiles.txt`）：

| id | 目標選擇 | aggression | guardHp |
|---|---|---|---|
| `rusher` | 最近 | 90 | 0 |
| `cautious` | 最近 | 40 | 30 |
| `hunter` | HP 最低 | 75 | 0 |

> ⚠️ **`group=` 目前完全沒有作用。** 它被解析進 `SpawnDef.Group` 之後沒有任何程式讀它。
> `stage01.encounter` 裡的 `group=north` / `group=east` 看起來像 XCOM 的 pod，
> **但啟動是逐單位的**（OD-10 / R-THR-03）。不要依賴它。

# 7. 怎麼跑

## Unity 內

- **跑分**：選單 `Ediki > Run Metrics`，輸出到 `<專案>/SimResults/`
- **試玩**：Play，`1`–`9` `0` `-` `=` `[` `]` 切地圖（`0` = 第 10 格），清單在
  [PrototypeBootstrap.SelectableEncounters](../../Assets/Scripts/Unity/PrototypeBootstrap.cs)
- **九個策略**：`corridor-hold` / `tpa-order` / `residue-aware` / `decapitate` /
  `control-hold` / `sustain-hold` / `shield-wall` / `purify-hold` / `charge`
  —— 除了 `charge`，全部繼承 `corridor-hold` 且只覆寫一個鉤子

## Unity 外（`dotnet`，Core / Sim 零引擎依賴）

scratchpad 內建臨時專案，不在版控。做法見
[HANDOFF §5](../HANDOFF-NEXT-SESSION.md)，四種都驗證過：跑分、EditMode 測試、
Unity 層編譯檢查、Editor 層編譯檢查。

## 跑分設定的意義

| 參數 | 值 | 它是什麼 |
|---|---|---|
| 場次 | **200 / 格** | 慣例 |
| base seed | 1 | 同 seed 完整重現 |
| noise | **15%** | **取樣裝置，不是遊戲規則**。沒有它，確定性規則 ＋ 確定性策略每次跑同一場，分布零變異 |
| round cap | **60** | **跑分工具的安全網，不是規則**。R-WIN-04：規則層沒有回合上限。踩到的場次另計為 unresolved |

# 8. golden hash 的紀律

架構測試 **A4** 用常數比對狀態雜湊。改 Core 之後它失敗是**刻意的**。

```
A4 失敗時，先問：這次改動應該改變模擬結果嗎？
    不應該 → 你引入了 bug 或不確定性。不要更新 hash，去修 bug
    應該   → 更新常數，並在 CHANGELOG 說明為什麼結果變了
```

> **「A4 壞了就更新常數」是最危險的習慣。**
> 它會讓這條測試從確定性守門員退化成橡皮圖章。

**新增狀態欄位時請照這個模式做**：只在該欄位確實被用到時才折進雜湊。
污染陣列（沒污染時保持 null）與斬首標記（沒標記時不折）都是這樣做的，
所以兩次規則擴充**都沒有動到 A4**，golden 常數保住了意義。

# 9. 你沒問但一定會踩的（全部是量出來的）

### 9.1 敵人自己會過來，所以「要不要接近」不是玩家的決定

[OD-16](../OPEN-DECISIONS.md#od-16)：敵人從第 1 回合就主動接敵。
**戰鬥自己送上門，玩家沒有理由旅行。**

- rout 目標下 175/200 場從未踏上分隔牆那一列。改地圖修不好
- 斬首目標下也只有 22/200 場踏上去 —— 紙上模型算的是「要不要走過去」，
  引擎裡發生的是「**要不要忍住**」
- **`test_turret`（`move=0`）是唯一把這個決定還給玩家的原型**，
  而它立刻給出全專案最大的策略落差（65）

### 9.2 高 DEF 做不出 Boss

減法公式 `max(1, ATK−DEF)` 下，`test_blocker` / `kohaku_tank`（ATK 40）
對桃太郎 DEF 50 只有**保底 1 傷**。略過它完全免費，投資取捨根本不會出現。
**硬度只能來自 HP。**

同一件事的另一面：減法讓低攻單位**對高防目標歸零**。
正守（ATK 33）打 DEF 45 的牆，每擊只有保底 1 傷 → **120 刀**；
換成百分比減傷是 **7 刀**。他不是輸出低，是完全無法處理這個目標。

**減法製造硬性剋制，百分比製造軟性分工。**
這不是平衡問題，是「帶錯隊伍就打不動 vs 只是比較慢」的語言選擇 →
[OD-27](../OPEN-DECISIONS.md#od-27)。

### 9.3 「退款型」改動一律降低決策密度（已經量到三次）

| 改動 | 結果 |
|---|---|
| 加入正守（容錯支柱） | M5 落差 23 → **3** |
| `hold` 目標（指定玩家位置） | 長 N 時等同 rout |
| 淨化（4 AP 換每擊少吃 10 點） | 勝率 31% → **0%** |

**「容錯支柱」與「站位很重要」天生互相抵消。**

### 9.4 EP / TPA 有兩個已知失效模式

| 失效 | 為什麼 |
|---|---|
| **成長型敵人** | EP 把它評為全場最低威脅。所有靜態指標都是第 1 回合的快照，**時間不在它們的定義裡** |
| **斬首目標** | 被標記者永遠是 TPA 最低的（50 / 33 / 25 / 16），**越硬排得越後面** |

兩者都不是公式算錯，是**公式沒有那個維度**。

### 9.5 單一指標的誤讀清單

| 不要 | 為什麼 |
|---|---|
| **單看 M4 判斷誰比較安全** | `arena-stagger` 上 M4 說守勢安全，M7 說守勢待在射程裡的時間是 10 倍。**贏的是 M7 說的那個** |
| **把 M6 當成「玩家在做選擇」的證據** | 它**只能證偽**。固定策略永遠有固定偏好：同一張圖 `corridor-hold` 走 26/43/29、`charge` 走 3/96/0 |
| **跨隊伍人數比較 M1 的種類數** | 組合鍵把所有單位的動作合起來數，多一個單位本來就會膨脹。**要比就比 M1b** |
| **拿接觸回合比較輸掉的場次** | 死得早 = 接觸回合天然低。只在勝場之間比，或除以回合數 |
| **只看 `corridor-hold` 就下結論** | 斬首目標刀數 4 那列：rout 9% → kill 11%（雜訊內），同一列 `decapitate` 是 **31%** |

### 9.6 換單位比換公式危險

地形成本改存百分之一 AP 之後，`DistanceIn` 回傳值變成 100 倍，
**悄悄把每個策略的距離權重放大了 100 倍**。症狀只是勝率從 19% 掉到 9%。

> **公式改錯會編譯失敗，單位改錯只會讓數字變得不對。**

### 9.7 自動化跑分回答不了 Q2 與 Q4

- **Q2**「玩家會不會自己發現走廊？」—— 學習行為，AI 不會學
- **Q4**「玩家會不會把失敗歸因到運氣？」—— 心理現象

**「跑 1000 場」不等於「Prototype 驗證完成」。** 排程時要留人工 playtest 的時間。

### 9.8 不要為了讓數字好看而調數值

已經犯過兩次。跑分是**量測**，不是調參迴圈 ——
把難看的數字量出來、寫下來、登錄成 OD，才是這台機器的用途。
