# 1. 我目前已經理解到什麼

依你的要求，用「模型前提 → 結論 → 適用範圍 → 失效條件」複述既有結論，
**不推翻，只標定邊界**。

## 1.1 「幾刀」主要影響節奏，不直接產生 Target Priority

```
模型前提  同質敵人；傷害不隨血量衰減；所有敵人都打得到；無成長
結論      同質敵人不論設幾刀，最佳與最差擊殺順序的承傷差距 1.00–1.17 倍
適用範圍  「刀數」這個旋鈕單獨作用時
失效條件  ① 敵人異質且 EAtK 不整除 APT（見 §10 Action Residue）
          ② 存在接近成本差異（見 §8）
          ③ 存在威脅衰減門檻（見 §11 反例 5）
```

**本輪新增的邊界**：這個結論在 `APT = 1` 時**完全成立**（連續情形），
在 `APT ≥ 2` 時**部分失效** —— 量化會讓刀數重新產生影響，但只在特定格。

## 1.2 純傷害競賽下，Target Priority 退化成排序問題

```
模型前提  P1 玩家每回合固定行動數，可任意分配
          P2 唯一勝負量是累計承傷
          P3 敵人不移動、可及性不變、無狀態
          P4 玩家不浪費行動
          P5 無隨機
結論      最佳擊殺順序 = 依 TPA = EDPT/EAtK 遞減排序（Smith's Rule / WSPT）
適用範圍  上述五個前提全部成立時
失效條件  ★ P3 一旦鬆動（敵人有接觸延遲），問題從 1||Σw_jC_j
          變成帶釋放時間的排程，**貪婪解不再最佳**（§8 已驗證）
          ★ P1 的「固定行動數」造成量化，TPA 相等時仍可能不等價（§7）
```

## 1.3 EAtK／接近成本是目前最強的 Priority 改變因素

```
模型前提  接近成本可以折算成「額外的行動數」加進 EAtK 的分母
結論      k 每 +1，後排目標的 TPA 大幅下降，最佳開局可能翻轉
適用範圍  接近成本是一次性的（走過去就結束）
失效條件  ★ 若接近成本是「延後接觸」而非「多花行動」，兩者數學性質完全不同：
          前者改分母（仍可貪婪），後者是釋放時間（貪婪失效）。
          **這是本輪最重要的修正，見 §8.3。**
```

> ⚠️ **本輪對既有結論的唯一實質修正**：
> 上一份報告把「接近成本」當成 EAtK 的一部分（進分母）。
> 這在「敵人站著不動、你走過去打」時正確。
> 但當它是「敵人要 n 回合才走到你面前」時，它是**釋放時間**，
> 數學性質完全不同，而且**更強**。詳見 §8。

# 2. Metrics Framework

## 2.1 三層分類（最重要的一張表）

不是所有指標都是同一種東西。混用是最常見的錯誤。

| 層級 | 意義 | 特徵 | 例子 |
|---|---|---|---|
| **原始變數（Primitive）** | 設計師直接填的數字 | 可以自由設定；彼此獨立 | Player Damage、Enemy HP、APT、Movement Cost、Range、Growth Rate、Enemy 數量 |
| **衍生指標（Derived）** | 由原始變數算出來 | **不可獨立設定**；改它等於改上游 | Required Hits、AtK、UTK、EAtK、EDPT、TPA、Divisibility、Action Residue |
| **結果指標（Outcome）** | 要跑模擬或求解才知道 | **依賴玩家策略**；不能事先排序 | Realised Threat、ETBD、Regret、NOAR、Decision Density、Priority Reversal Point |

> **最常見的錯誤**：把結果指標當成可以調的旋鈕。
> 「我要把 Decision Density 調到 0.4」是沒有意義的句子 ——
> 你只能調原始變數，然後**量** Decision Density。

## 2.2 五個家族

| 家族 | 回答什麼問題 | 指標 |
|---|---|---|
| **Combat Economy** | 打死它要花多少？ | PD、EHP、RH、AtK、UTK、EAtK、EDPT、TPA、ETBD、Opportunity Cost、Action Residue、Divisibility |
| **Spatial Economy** | 打不打得到？站哪裡？ | Movement Cost、Range、Reachability Cost、Accessibility、**Static Exposure**、**Effective Exposure**、Positioning Cost、Release Time |
| **Temporal Economy** | 什麼時候會來不及？ | Growth Rate、Growth Mode、Future Threat、Threat Deadline、Escalation Rate、Time-to-Critical |
| **Decision Quality** | 這個局面有沒有決策？ | NOAR(τ)、Spread、Effective Choices、Regret（三種）、Regret Distribution Shape、Priority Reversal Point |
| **Objective Economy** | 除了殺人還有什麼值得做？ | Kill Value、Control Value、Position Value、Threat Removal Value、Objective Pressure |

> **Objective Economy 這一族本輪只做了定義，沒有建模。**
> 原因見 §14 —— 它需要一個「非承傷」的勝負量，而本輪模型只有承傷一個目標函數。

# 3. 各指標詳解

## 3.1 完整模板（核心 8 個）

### ① Required Hits (RH)

| | |
|---|---|
| **A. Definition** | 擊殺一個敵人需要命中幾次 |
| **B. Formula** | `RH = ceil(EnemyHP / max(1, PlayerATK − EnemyDEF))` |
| **C. Intuition** | 桃太郎每刀砍 40，小耗 80 血 → 兩刀 |
| **D. 能解釋** | 清場節奏；溢出傷害（overkill）的浪費量 |
| **E. 不能解釋** | **目標優先級。** 同質敵人下 RH 改動對擊殺順序幾乎無影響（1.00–1.17 倍） |
| **F. Interaction** | `PD, EHP → RH → AtK → EAtK → TPA` |
| **G. Failure Case** | 兩個 RH 相同的敵人，若一個在牆後，它們的實際處理成本完全不同 |
| **H. 用途** | **Balance Metric**（節奏），**不是** Player Decision Metric |

### ② Effective Actions-to-Kill (EAtK)

| | |
|---|---|
| **A. Definition** | 從「現在」到「它死掉」所需的玩家行動總數，含接近成本 |
| **B. Formula** | `EAtK = RH + ceil(接近所需 AP / 每行動 AP)`　（**僅適用於玩家主動接近的情形**） |
| **C. Intuition** | 後排弓兵 2 刀能殺，但要先走兩步 → 實際要 4 個行動 |
| **D. 能解釋** | 為什麼玩家會放著高傷敵人不管；地形/射程如何改變優先級 |
| **E. 不能解釋** | **非傷害型的處理方式**（推開、控制、繞過）。它假設「處理 = 擊殺」 |
| **F. Interaction** | `Movement Cost + Range + Position → Reachability → EAtK → TPA` |
| **G. Failure Case** | **敵人會自己走過來時（如本專案 OD-16），接近成本不該進 EAtK**，<br>而該表示成釋放時間 → §8.3 |
| **H. 用途** | **Encounter Metric** |

### ③ Enemy Damage per Turn (EDPT)

| | |
|---|---|
| **A. Definition** | 一隻敵人在一個回合內能造成的傷害 |
| **B. Formula** | `EDPT = max(1, EnemyATK − PlayerDEF) × 敵方每回合攻擊次數` |
| **C. Intuition** | 小耗 100 − 桃太郎 50 = 50/刀，每回合 2 刀 = 100 |
| **D. 能解釋** | 威脅的**上界** |
| **E. 不能解釋** | **實際造成的傷害。** 打不到你的敵人 EDPT 再高都是 0 |
| **F. Interaction** | 是 TPA 的分子；但需被 Exposure / Release 修正才等於實際威脅 |
| **G. Failure Case** | EDPT 200 但永不接觸 vs EDPT 30 但穩定命中 → 後者優先（§8 實測） |
| **H. 用途** | **Balance Metric**（上界），不可直接當 Difficulty Metric |

### ④ Threat per Action (TPA)

| | |
|---|---|
| **A. Definition** | 每花一個行動能消除多少「每回合傷害」 |
| **B. Formula** | `TPA = EDPT / EAtK` |
| **C. Intuition** | 「這個目標划不划算」 |
| **D. 能解釋** | **在五個前提下**，依 TPA 遞減擊殺 = 最小化總承傷（Smith's Rule，已窮舉驗證） |
| **E. 不能解釋** | ① 接觸延遲 ② 成長 ③ 量化造成的平手破除 ④ 非傷害價值 |
| **F. Interaction** | `EDPT, EAtK → TPA → Target Priority` |
| **G. Failure Case** | **TPA 相等 ≠ 實際等價。** APT ≥ 2 時，TPA 相同的兩個目標可能差 15 點傷害（§7.1） |
| **H. 用途** | **Player Decision Metric**（作為玩家心算的近似），**Encounter Metric**（作為設計檢查） |

### ⑤ Static / Effective Exposure

> **本專案已有這兩個定義**，見 [SPEC-grid-terrain §3.2](03-spec/SPEC-grid-terrain.md)。
> **不另創名詞。**

| | |
|---|---|
| **A. Definition** | 靜態：該格的可通行相鄰格數（地圖固有性質）<br>有效：其中敵人**這回合實際到得了**的數量 |
| **B. Formula** | `StaticExp(c) = #{相鄰格 c' : 可通行且敵人可佔據}`<br>`EffExp(c, t) = #{存活敵人 e : c ∈ ThreatRange(e, t)}` |
| **C. Intuition** | 靜態＝這格最多幾面受敵；有效＝這回合真的幾面受敵 |
| **D. 能解釋** | 站位的價值；為什麼隘口有用 |
| **E. 不能解釋** | **未來的威脅。** 有效 Exposure 是**當下**快照，看不見「兩回合後會被包圍」 |
| **F. Interaction** | `地圖幾何 → StaticExp`；`StaticExp + 敵人位置 + Movement → EffExp → Release Time` |
| **G. Failure Case** | 靜態 Exposure 1 的黃金格，若敵人主動接敵，它只是延後接觸，不是免疫（本專案 OD-16 的實際後果） |
| **H. 用途** | **Player Decision Metric**（有效）＋ **Encounter Metric**（靜態） |

### ⑥ Release Time（接觸回合）🆕

| | |
|---|---|
| **A. Definition** | 敵人 j 第幾回合起才真的打得到玩家 |
| **B. Formula** | `r_j = min{ t : 玩家預定位置 ∈ ThreatRange(j, t) }` |
| **C. Intuition** | 「它還要兩回合才走得到我面前」 |
| **D. 能解釋** | 為什麼高 EDPT 的遠處敵人優先級低；為什麼走位可以「買時間」 |
| **E. 不能解釋** | 它本身不含傷害量，必須與 EDPT 一起用 |
| **F. Interaction** | `Movement + Range + 玩家位置 → Release Time`；<br>`Release Time + EDPT → Realised Threat` |
| **G. Failure Case** | 玩家自己會移動，所以 `r_j` 不是常數，是玩家策略的函數 → **它其實是結果指標** |
| **H. 用途** | **Encounter Metric**；**這是本輪找到最有價值的新指標**，理由見 §8 |

### ⑦ Action Residue

| | |
|---|---|
| **A. Definition** | 本回合用不完、且不足以完成任何一次擊殺的行動 |
| **B. Formula** | `Residue = APT − (用於完成擊殺的行動數)`；<br>結構性零頭：`(−EAtK) mod APT` |
| **C. Intuition** | 「我還有一個行動，但殺不掉任何東西，該幹嘛？」 |
| **D. 能解釋** | 1 刀雜魚為什麼有不可取代的價值；為什麼整除會消滅決策 |
| **E. 不能解釋** | 零頭本身的價值 —— 那取決於場上有沒有東西可以吃掉它 |
| **F. Interaction** | `EAtK, APT → Divisibility → Action Residue → Decision Density` |
| **G. Failure Case** | 若規則允許「保留行動到下回合」（本專案的 AP carryover 就是），零頭可以被儲存，**這個指標的結構性部分失效** |
| **H. 用途** | **Encounter Metric** |

### ⑧ Regret

| | |
|---|---|
| **A. Definition** | 選了某個行動，相對最佳解損失多少 |
| **B. Formula** | 相對：`(Chosen − Optimal)/Optimal`　絕對：`Chosen − Optimal`<br>正規化：`(Chosen − Optimal)/Budget`（Budget 例如玩家總 HP） |
| **C. Intuition** | 「這步棋虧了多少」 |
| **D. 能解釋** | 選錯的代價；關卡的容錯度 |
| **E. 不能解釋** | **玩家知不知道答案。** Regret 是全知者的量，與可學習性無關 |
| **F. Interaction** | `所有合法行動 → 結果分布 → Regret 分布 → Decision Density` |
| **G. Failure Case** | ★ **最佳解 = 0 承傷時，相對 Regret 無定義**，且會沉默地回報 0（§11 反例 3） |
| **H. 用途** | **Difficulty Metric** ＋ **Player Decision Metric** |

## 3.2 其餘指標（壓縮格式）

| Metric | Formula / Definition | 能解釋 | 不能解釋 | 主要 Failure Case |
|---|---|---|---|---|
| Player Damage | `max(1, ATK−DEF)` | RH 的分母 | 命中率、範圍傷害 | 除法減傷公式下邊際遞減 |
| Enemy HP | 原始值 | 清場節奏 | 優先級 | 見 §1.1 |
| Attacks per Turn | `floor(AP/attackCost)` | 量化粒度 | 何時該用來移動 | FE 的追擊讓它變成單位屬性而非常數 `[External Fact]` |
| Action-to-Kill | `RH × attackCost` | AP 預算佔用 | 移動的機會成本 | AP 上限/carryover 會鬆動它 |
| Unit-Turns-to-Kill | `RH / APT` | 「幾個完整回合」 | 多單位協同 | 多單位時分母不唯一 |
| Movement Cost | 每格 AP | 接近成本 | 阻擋與繞路 | 曼哈頓距離看不見牆（本專案 OD-18 付過代價） |
| Attack Range | 原始值 | 可及性 | 視線遮蔽 | 若有 LOS 規則則不足 |
| Reachability Cost | 路徑距離（非曼哈頓） | 真實接近成本 | 敵人也會動 | 雙方都移動時它是賽局，不是距離 |
| Opportunity Cost | 做 A 而沒做 B 的損失 | 移動 vs 攻擊的取捨 | 需要先有 B 的估值 | 若 B 是非傷害價值則無法計價 |
| Divisibility | `EAtK mod APT` | 零頭存在與否 | 零頭值不值錢 | carryover 會破壞它 |
| ETBD | `EDPT × (死亡回合 − 接觸回合)` | 實際承傷歸因 | 事前排序（它是結果） | 依賴擊殺順序，不可當輸入 |
| Growth Rate | `dThreat/dt` | 未來威脅 | 當下威脅 | 不同 gmode 的同一個「率」不可比 |
| Threat Deadline | 最晚仍能守住預算的起手回合 | 時間壓力 | 玩家是否看得出來 | 需要玩家可觀測才有意義 |
| NOAR(τ) | 結果在最佳 τ 內的行動比例 | 好選擇的數量 | 選擇的**品質** | 對 τ、對代價零點、對對稱選項都敏感（§11） |
| Spread | 最差/最佳 | 選錯的最大代價 | 好選擇有幾個 | 最佳=0 時爆炸 |
| Effective Choices | `exp(H(softmax(−regret/T)))` | 連續版「有幾個真選項」 | 同樣受對稱污染 | 依賴溫度 T |

```

玩家/敵人位置 ─┘                                                        │
                                                                       ├─→ TPA ──→ TargetPriority
EnemyATK ─┐                                                            │            （排序，僅在 §1.2
PlayerDEF ─┼─→ EnemyDamage ─→ EDPT ────────────────────────────────────┘             五前提下有效）
敵方APT   ─┘                          │
                                       │

敵人位置 ──┐                 ├─→ EffectiveExposure ──→ ★ReleaseTime ──┐
Movement ─┴─────────────────┘                                        │
                                                                     ├─→ ★RealisedThreat
GrowthRate ─┬─→ FutureThreat(t) ──→ ThreatDeadline ───────────────────┘        │
GrowthMode ─┘                                                                  │
                                                                               ↓
EAtK, APT ──→ Divisibility ──→ ActionResidue ──────────────────────→ 【局面求解】
                                                                               │
                                                    ┌──────────────────────────┤
                                                    ↓                          ↓
                                            所有合法行動的結果分布        最佳解 / 最差解
                                                    │                          │
                                    ┌───────────────┼──────────────┐           │
                                    ↓               ↓              ↓           ↓
                                 NOAR(τ)      Regret 分布    EffectiveChoices  Spread
                                    └───────────────┴──────────────┴───────────┘
                                                    ↓
                                            DecisionDensity
                                          （需要 NOAR + Spread 兩者，見 §5）
```

**三條必須記住的規則**：

1. **★ 標記的兩個（ReleaseTime、RealisedThreat）是結果指標，不是輸入。**
   它們依賴玩家的走位與擊殺順序，不能事先排序。
2. **不要重複計算接近成本。** 它要嘛進 `EAtK`（玩家主動接近），
   要嘛進 `ReleaseTime`（敵人主動接近）——**兩者擇一，不可同時**。
3. **Decision Density 在圖的最下游。** 它是所有原始變數的函數，
   所以「直接調 Decision Density」是不可能的。

# 5. Decision Density 深入

## 5.1 你舉的例子：NOAR 分辨得出來嗎？

`[Model]` 把分數轉成代價（代價 = 200 − 分數）：

| 局面 | NOAR(5%) | NOAR(10%) | NOAR(20%) | EffChoices | meanRegret | maxRegret |
|---|---|---|---|---|---|---|
| **P** (100/99/97/40) | **0.75** | 0.75 | 0.75 | 2.92 | 16.0% | 60.0% |
| **Q** (100/50/30/10) | **0.25** | 0.25 | 0.25 | 1.00 | 52.5% | 90.0% |

**分辨得出來。** 但立刻出現第一個問題。

## 5.2 問題一：NOAR 依賴「代價的零點」

`[Model]` 同一組分數，只改換算原點：

| 代價原點 | P 的 NOAR(5%) | P 的 EffChoices | Q 的 NOAR(5%) |
|---|---|---|---|
| 110 | **0.25** | 1.46 | 0.25 |
| 150 | 0.50 | 2.71 | 0.25 |
| 200 | **0.75** | 2.92 | 0.25 |
| 400 | 0.75 | 3.09 | 0.25 |

> `[Inference]` **NOAR 是相對量，會隨零點漂移。**
> 在戰棋裡「累計承傷 = 0」是天然零點，所以**用承傷當代價時安全**。
> **但拿去量「剩餘 HP」「關卡分數」這類沒有天然零點的量時，NOAR 沒有意義。**
>
> **實務規則**：NOAR 只能用在有天然零點的量上。

## 5.3 問題二：5% 不該是固定值

`[Model]` NOAR(τ) 對 τ 的敏感度：

| 情境 | τ=1% | 2% | 5% | 10% | 20% | 30% | EffChoices | Spread |
|---|---|---|---|---|---|---|---|---|
| A 1刀雜魚×3 + 3刀菁英 | 0.43 | 0.43 | 0.43 | 0.43 | **1.00** | 1.00 | 4.26 | 1.12 |
| B 全 2 刀（完全整除） | 0.17 | 0.17 | 0.17 | 0.17 | 0.17 | 0.17 | 1.02 | 2.00 |
| B' 同上但 APT=3 | 0.29 | 0.29 | 0.29 | 0.29 | 0.29 | 0.29 | 2.00 | 2.00 |
| 同質 4×(2刀/100傷) | 0.40 | 0.40 | 0.40 | 0.40 | **1.00** | 1.00 | 4.99 | 1.17 |

> `[Inference]` **NOAR(τ) 曲線的形狀本身才是資訊**，單一數字不是。
> - 情境 B 的曲線**完全平坦** → 真的只有一個解，不管你多寬容
> - 情境 A 在 τ=10→20% 之間**跳到 1.00** → 有一個明確的「及格線」
>
> **建議報告方式**：至少報 5 / 10 / 20 三個點，或報「NOAR 跳到 1.0 的 τ」。

## 5.4 問題三（最嚴重）：NOAR 分不出「很多好選擇」與「所有選擇都沒差」

看「同質 4×小耗」：NOAR(20%) = 1.00，EffChoices = 4.99。
**看起來決策非常豐富。實際上四隻敵人完全相同，先打誰都一樣。**

`[Inference]` **必須把 NOAR 與 Spread 一起看。** 四象限：

| | Spread 大（選錯很痛） | Spread ≈ 1（選錯沒差） |
|---|---|---|
| **NOAR 小** | ① **唯一解** —— 玩家在背答案 | （不可能） |
| **NOAR 大** | ② ⭐ **真決策** —— 多個好解＋明確陷阱 | ④ **無關緊要** —— 沒有決策 |

`[Model]` 實測分類：

| 情境 | NOAR(5%) | Spread | 象限 |
|---|---|---|---|
| A 1刀雜魚×3 + 3刀菁英 | 0.43 | 1.12 | ② 真決策 |
| B 全 2 刀 | 0.17 | 2.00 | ① 唯一解 |
| B' 全 2 刀 APT=3 | 0.29 | 2.00 | ② 真決策 |
| 同質 6×1刀 | 1.00 | 1.00 | ④ 無關緊要 |
| 威脅衰減 prop | 1.00 | 1.00 | ④ 無關緊要 |
| 威脅衰減 threshold | 0.50 | 1.14 | ② 真決策 |

## 5.5 結論：Decision Density 的建議定義

> `[Hypothesis]` **Decision Density 不是單一數字，是一個二元組：**
> ```
> DecisionDensity = ( NOAR(τ) 曲線 , Spread )
> ```
> 附帶兩個必要的清洗步驟：
> 1. **對稱合併** —— 把「打 k0」與「打 k1」這種對稱選項算成同一個
>    （否則同質敵人會灌水，見 §11 反例 4）
> 2. **代價須有天然零點**
>
> **本輪不建議把它合併成單一分數。** 理由見 §13 的第 11 條原則。

# 6. Regret 深入

## 6.1 三種 Regret，各有適用範圍

| 版本 | 公式 | 何時用 | 何時失效 |
|---|---|---|---|
| 相對 | `(C − O)/O` | O > 0 且量級穩定 | **O = 0 時無定義** |
| 絕對 | `C − O` | O 可能為 0 | 跨關卡不可比（量級不同） |
| 正規化 | `(C − O)/Budget` | 跨關卡比較 | 需要先定義 Budget |

## 6.2 一個真實的沉默失效 `[Model]`

情境：`A(EAtK 2, EDPT 50, release 2)`、`B(EAtK 2, EDPT 30, release 0)`，APT=2。

- 最佳打法：先殺 B（1 回合），再殺 A（A 還沒接觸）→ **總承傷 0**
- 最差開局 → 總承傷 30

**相對 Regret 的計算結果是 0%，而且不會報錯。**
它會讓你以為「這個局面沒有決策」，實際上它有一個**完美解**與一個明確的錯誤。

> `[Inference]` **這是最危險的一類指標失效：它不是給出錯的答案，是給出「沒問題」的答案。**
> 實務規則：**任何時候最佳解可能為 0，就必須用絕對或正規化版本。**

## 6.3 「錯誤選擇應該有代價但不該立刻 Game Over」——不要直接假設答案是對的

`[Model]` 把它拆成可檢查的量：

```
maxRegret（正規化） = (最差選擇的承傷 − 最佳承傷) / 玩家可承受總量
maxRegret ≥ 1.0  ⇒  一次錯誤選擇 = 立刻死亡
```

`[External Fact]` **本專案目前就在 ≥ 1.0 這一側**，而且是文件明載的：
[OD-20](OPEN-DECISIONS.md#od-20) 記錄 `小耗 ATK 100 − 桃太郎 DEF 50 = 50/擊 ×2 ×3 隻 = 300 = 桃太郎全部 HP`，
即 **Exposure 3 以上就是單回合陣亡**。

`[External Fact]` 但同一份 OD 也記錄了反面：把 ATK 降到 70（讓 maxRegret < 1）之後，
**守勢與衝鋒的勝率落差從 48 掉到 1** —— 站位完全失去意義。

| 小耗 ATK | 一次大失誤的後果 | M5 技術落差 |
|---|---|---|
| 70 | 活得下來 | **1** ❌ |
| 85 | 重傷 | 25 |
| 100 | **當回合死亡** | **48** ✅ |

> `[Inference]` **在這個專案的實測資料裡，「錯誤要有代價但不要立刻死」與
> 「站位要有意義」是互相衝突的，不是互補的。**
>
> 所以那句設計格言**不是普遍真理**，它是一個取捨位置。
> 本專案目前刻意選了「立刻死」那一端，並用完全資訊
> （[battle-experience](02-design/battle-experience.md)「威脅範圍是資源，不是陷阱」）
> 來讓它變得可接受 —— **不是靠降低懲罰，是靠讓玩家事先看得見。**
>
> `[Hypothesis]` 高 maxRegret 的可接受性取決於**資訊完全度**，不取決於懲罰大小本身。
> **需要的實驗**：同一組數值下，開／關危險區顯示，比較真人玩家的挫折回報。
> 目前不裁決。

## 6.4 Regret 分布的形狀比平均值有用 `[Model]`

| 情境 | mean | max | median | 形狀 | 讀法 |
|---|---|---|---|---|---|
| A 1刀×3+3刀菁英 | 7.1% | 12.5% | 12.5% | 均勻 | 大部分選項都差不多錯 |
| B 全 2 刀 | 50.0% | 100.0% | 66.7% | **陡峭** | 多數選項是錯的 → 背答案 |
| 威脅衰減 threshold | 7.1% | 14.3% | 14.3% | 均勻 | |
| 同質 6×1刀 | 0% | 0% | 0% | **全平** | 沒有決策 |

> `[Hypothesis]` 最健康的形狀是**長尾**：中位數接近 0（大部分開局都行），
> 但最大值明顯（存在少數陷阱）。
> **本輪的紙上情境沒有一個產生長尾**——它們都太小了（3–5 個敵人）。
> 長尾可能需要更大的局面才會出現。**這是下一輪值得檢查的事。**

# 7. Priority Reversal 深入

## 7.1 你給的臨界例：TPA 相等時真的等價嗎？ `[Model]`

```
Minion: EDPT=30, EAtK=2 → TPA=15
Elite : EDPT=45, EAtK=3 → TPA=15
```

| APT | 先雜魚 | 先菁英 | 精確最佳 | 結論 |
|---|---|---|---|---|
| **1** | 210 | 210 | 210 | **完全等價 ✅ TPA 說對了** |
| **2** | **90** | 105 | 90 | ❌ 差 15 |
| **3** | 45 | **30** | 30 | ❌ 差 15 |
| **4** | 45 | **30** | 30 | ❌ 差 15 |

> `[Inference]` **只有 APT = 1（連續情形）時 TPA 相等才代表真的等價。**
> APT ≥ 2 一律不等價 —— 而且**翻轉方向會隨 APT 改變**
> （APT=2 先打雜魚，APT=3 先打菁英）。
>
> **Priority Boundary 不是一條線，是一組隨 APT 變化的階梯。**

## 7.2 Priority Boundary Map `[Model]`

Minion 固定 `EDPT=30 / EAtK=2`，APT=2。掃 Elite：
（`M` = 先打雜魚較優，`E` = 先打菁英較優，`=` 完全等價）

| Elite EDPT \ EAtK | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|
| 20 | M | M | M | M | M | M |
| 30 | **=** | **=** | M | M | M | M |
| 40 | E | E | M | M | M | M |
| 45 | E | E | M | M | M | M |
| 50 | E | E | M | M | M | M |
| 60 | E | E | **=** | **=** | M | M |
| 80 | E | E | E | E | M | M |
| 100 | E | E | E | E | E | E |

> `[Inference]` 三個觀察：
> 1. 邊界**不是** TPA=15 那條斜線。TPA 預測 `EDPT=15×EAtK` 為界
>    （EAtK=3 → 45），但實測 EDPT=45 / EAtK=3 是 **M**，不是 `=`。
> 2. `=` 出現在**整除處**（EAtK ∈ {2,4} 對 APT=2）。
>    **整除性把連續邊界打成階梯。**
> 3. 邊界是一條**帶狀區域**，不是線。設計時若想讓玩家「需要思考」，
>    應該把敵人放進那條帶子裡，而不是追求某個精確的 TPA 值。

## 7.3 加入 Release 之後，邊界大幅移動 `[Model]`

| release | EDPT=100 那一列的結果（EAtK 1→6） |
|---|---|
| 0 | E E E E E E |
| 1 | M M **E E E E** |
| 2 | M M M M **E E** |
| 3 | **M M M M M M** |

> `[Inference]` **release 每 +1，「先打菁英」的區域就大幅退縮。**
> release=3 時，即使 EDPT 高達 100（雜魚的 3.3 倍）也全部讓位給雜魚。
>
> **這證明 Threat Exposure 不是 TPA 的一個修正項，而是一個獨立的維度。**

# 8. Threat Exposure 深入（本輪最重要的一節）

## 8.1 你的問題的答案 `[Model]`

```
Enemy A: EDPT=50，目前打不到玩家
Enemy B: EDPT=30，目前可以穩定攻擊
```

| A 的 release | 先打 A | 先打 B | 精確最佳 | 誰優先 |
|---|---|---|---|---|
| **0** | **30** | 50 | 30 | 先打 A |
| **1** | 30 | **0** | **0** | **先打 B** |
| 2–6 | 30 | **0** | **0** | 先打 B |

> **交叉點在 release = 1。**
> A 只要晚**一個回合**才接觸得到，它的優先級就輸給 EDPT 只有它 60% 的 B。

## 8.2 正確的威脅單位

| 敵人 | EDPT | 實際接觸回合數 | **實際總傷害** |
|---|---|---|---|
| A 高傷但延遲接觸 | 50 | 2 | 100 |
| B 低傷但立即接觸 | 30 | 5 | **150** |
| C 極高傷但永不接觸 | 200 | 0 | **0** |

> `[Inference]` **「威脅」的單位不是傷害/回合，是「它實際會打到你幾回合」。**
> ```
> RealisedThreat_j = EDPT_j × max(0, 死亡回合_j − 接觸回合_j)
> ```
> ⚠️ 它**依賴擊殺順序**，所以是**結果指標**，不能拿來事先排序。
> **這正是 Threat Exposure 無法被塞進 TPA 分子的數學原因。**

## 8.3 最強的理論結果：Release 讓貪婪解失效

`[Inference]` 這是本輪找到最乾淨的一件事：

| 條件 | 對應的排程問題 | 最佳解 |
|---|---|---|
| 所有敵人立刻可打（release 全 0） | `1‖Σ w_j C_j` | **Smith's Rule，貪婪多項式可解** |
| 敵人有接觸延遲 | `1│r_j│Σ w_j (C_j − r_j)⁺` | **一般為 NP-hard，不存在貪婪最佳解** |

`[Model]` 實測（`A(3,40,r=2)`、`B(2,30,r=0)`、`C(4,50,r=1)`，APT=2）：

| 方法 | 承傷 |
|---|---|
| TPA 排序 `[B, A, C]` | 150 |
| 窮舉最佳 `[B, C, A]` | **130** |

> **TPA 貪婪比最佳差 15%。**
>
> `[Inference]` **這是「讓 Smith's Rule 失效」最乾淨、且有理論保證的做法。**
> 而它剛好就是本專案已經在做的事：
> 威脅範圍、Exposure、隘口、地形削減威脅圈 —— 全部都是在操作 `r_j`。
>
> **也就是說：本專案押注的核心命題（站位比打誰重要），
> 在排程理論上有一個對應的、可證的理由。**
> 這是本輪最值得記下來的一句話。

## 8.4 哪些因素可以合理合併，哪些不行

你特別提醒不要硬塞成一個公式。實際檢查的結果：

| 因素 | 能不能併進同一個量？ |
|---|---|
| Movement Cost ＋ Attack Range ＋ 地形 | ✅ **可以**，全部併成「路徑成本 → release 或 EAtK」（本專案已經這樣做，`TerrainDistanceField`） |
| Static Exposure ＋ Effective Exposure | ❌ **不可以**。前者是地圖固有性質，後者是當下快照。專案文件已經明確分開，**這個分開是對的** |
| Release Time ＋ EDPT | ⚠️ **只能在結果端相乘**（RealisedThreat），**不能在輸入端合併成單一優先級分數** |
| EAtK ＋ Release Time | ❌ **絕對不可以**。§1.3 已說明：一個進分母、一個是釋放時間，數學性質不同 |
| LOS（視線） | 本專案無此規則，未建模 |

# 9. Threat Deadline 深入

`[Model]` 設定：成長敵人 EAtK=4，玩家 APT=2，可承受總傷害預算 300。
問「最晚第幾回合開始處理它」。

| 成長曲線 | 最晚開始回合 | t=3 威脅 | t=6 | t=10 | 決策形狀 |
|---|---|---|---|---|---|
| 緩慢線性 +5 | **8** | 25 | 40 | 60 | 幾乎沒有壓力 |
| 線性 +20 | 4 | 70 | 130 | 210 | 平滑：越拖越貴 |
| 線性 +40 | **3** | 130 | 250 | 410 | 平滑但很緊 |
| 指數 ×1.3 | 7 | 22 | 48 | 138 | 平滑偏後段加速 |
| 指數 ×1.6 | 5 | 41 | 168 | **1100** | ⭐ **懸崖** |
| 門檻 t≥5 ×8 | 7 | 10 | **80** | 80 | ⭐ **鬧鐘** |
| 門檻 t≥3 ×8 | 5 | **80** | 80 | 80 | 鬧鐘（更早響） |

> `[Inference]` 三種曲線給出三種**完全不同的玩家心理**：
>
> | 曲線 | 玩家的體驗 | 決策型態 | 適合用在 |
> |---|---|---|---|
> | **線性** | 「越拖越貴」 | **連續**微調，每回合重新權衡 | 持續張力 |
> | **指數** | 「有個懸崖，過了就完了」 | **一次性**重大決斷 | Boss、高潮關 |
> | **門檻** | 「有個鬧鐘會響」 | **可預告、可視覺化** | **教學關** |
>
> `[Hypothesis]` 門檻式最適合教學，因為它是唯一能**在觸發前就完整顯示給玩家看**的
> —— 這與本專案的完全資訊哲學相容。
> **需要的實驗**：真人 playtest 比較線性 vs 門檻的「玩家有沒有意識到時限」。
> 目前不裁決，且本輪不實作。

> ⚠️ **一個測量陷阱**：上表的「最晚開始回合」對「預算 300」這個數字非常敏感。
> 換一個預算，整張表的排序都可能變。**Threat Deadline 是相對於預算定義的，不是絕對量。**

# 10. Action Residue 深入

## 10.1 零頭到底值多少 `[Model]`

比較「雜魚設成 1 刀」相對「設成 2 刀」省下多少承傷：

| 菁英 EAtK | APT | 結構性零頭 | 1 刀雜魚省下的傷害 | |
|---|---|---|---|---|
| 2 | 2 | 0 | 20 | 整除 |
| 2 | 3 | **1** | 20 | ⭐ 有零頭 |
| **3** | **2** | **1** | **50** | ⭐ 有零頭 |
| 3 | 3 | 0 | 20 | 整除 |
| 4 | 2 | 0 | 20 | 整除 |
| 4 | 3 | **2** | 30 | ⭐ 有零頭 |
| **5** | **2** | **1** | **70** | ⭐ 有零頭 |

> `[Inference]` **零頭存在時，1 刀雜魚的價值是整除情形的 2.5–3.5 倍。**
> 這是 1 刀雜魚**唯一無法被取代的功能**。

## 10.2 零頭可以拿去做什麼 —— 以及哪些可以互相比較

| 用途 | 模型 | 價值 | 單位可比？ |
|---|---|---|---|
| ① 浪費 | — | 0 | — |
| ② 擊殺 1 刀雜魚 | 永久移除一個 EDPT 來源 | `EDPT_雜魚 × 剩餘回合數` | ✅ |
| ③ 部分傷害（不擊殺） | 無衰減規則下 | **恆為 0** | ✅（就是 0） |
| ③' 部分傷害（門檻式衰減） | 打過門檻 → 降檔 | `EDPT × (1 − 降檔倍率) × 剩餘回合` | ✅ |
| ④ 移動降低 Exposure | 少被 n 隻打到 | `ΔEffExposure × 單隻 EDPT` | ✅ |
| ⑤ 移動增加 release | 把某敵人推遲 n 回合 | `EDPT × n` | ✅ |

> `[Inference]` **②④⑤ 的單位都是「EDPT × 回合數」，所以可以直接互相比較。**
> 這是本輪找到**少數幾個可以合理合併**的地方 —— 而且它剛好統一了
> 「攻擊」與「走位」這兩種本來看似不同的行動。
>
> **③ 在目前規則下恆為 0，這就是「打殘沒有價值」的數學形式。**

> ⚠️ **本專案的一個結構性例外**：`units.txt` 的 AP 是 **cap 10 / regen 8**，
> 未用完的 AP **會結轉**。這代表零頭**可以被儲存到下一回合**，
> 所以「結構性零頭」在本專案裡是**部分失效**的。
> `[Hypothesis]` AP carryover 可能正在削弱 Action Residue 的決策價值。
> **需要的實驗**：紙上模型比較「有 carryover / 無 carryover」的 NOAR 與 Spread。
> 目前不裁決，且**不建議因此修改 AP 規則**。

# 11. Counterexamples：看起來合理但會失效的分析

## 反例 1 — 「TPA 相等 ⇒ 兩個目標等價」

**錯在哪**：TPA 是連續量，擊殺是離散事件。
**證據**：`Minion(30,2)` vs `Elite(45,3)` 兩者 TPA 都是 15，
但 APT=2 時先打雜魚省 15 傷、APT=3 時先打菁英省 15 傷（§7.1）。
**教訓**：**只有 APT=1 時 TPA 的平手才是真平手。**

## 反例 2 — 「照 TPA 排序永遠最佳」

**錯在哪**：一旦敵人有接觸延遲，問題變成帶釋放時間的排程，貪婪不再最佳。
**證據**：`[B,A,C]`（TPA 排序）150 vs `[B,C,A]`（最佳）130，差 15%（§8.3）。
**教訓**：**Smith's Rule 的前提 P3（可及性不變）是它最脆弱的一條。**

## 反例 3 — 「Regret = 0 代表沒有決策」★ 最危險

**錯在哪**：相對 Regret 在最佳解 = 0 時無定義，程式會沉默回傳 0。
**證據**：`A(2,50,r=2)` + `B(2,30,r=0)`，最佳打法承傷 **0**、最差 **30**，
相對 Regret 計算結果卻是 **0%**（§6.2）。
**教訓**：**這類失效不是給錯答案，是給出「沒問題」的答案。**
最佳解可能為 0 時，一律用絕對或正規化 Regret。

## 反例 4 — 「NOAR 高 ⇒ 決策豐富」

**錯在哪**：NOAR 數的是**帶標籤的行動**，不是**不同的策略**。
**證據**：4 隻完全相同的敵人，NOAR(20%) = 1.00、EffChoices = 4.99，
但「打第 1 隻」與「打第 2 隻」是同一個策略（§5.4）。
**教訓**：算 NOAR 之前必須先做**對稱合併**。

## 反例 5 — 「讓受傷敵人變弱，打殘就有價值了」

**錯在哪**：完全比例衰減時，每個行動阻止的傷害都一樣多 → 所有順序等價。
**證據**：比例衰減下 Spread = 1.00、NOAR = 1.00（象限④，決策歸零）；
門檻式衰減 Spread = 1.14、NOAR = 0.50（象限②，真決策）。
**教訓**：**衰減曲線的形狀比「有沒有衰減」重要得多。**

## 反例 6 — 「NOAR 可以拿來比較不同關卡」

**錯在哪**：NOAR 依賴代價的零點。
**證據**：同一組分數改換算原點，NOAR(5%) 從 0.25 變到 0.75（§5.2）。
**教訓**：只能用在有天然零點的量（累計承傷有，剩餘 HP 沒有）。

## 反例 7 — 「動作組合種類越多 = 決策空間越大」（本專案已付過代價）

`[External Fact]` [OD-26](OPEN-DECISIONS.md#od-26)：加入正守後 M1 種類從 44 → 179，
但 M5 技術落差從 23 → 3。**多樣性暴增、意義歸零。**
**教訓**：這是反例 4 在專案實測上的同一個現象 —— **計數指標會被組合數灌水。**

## 反例 8 — 「雜魚越多，玩家越應該先清雜魚」

`[Model]` 上一輪實測：雜魚 2 隻時成長型要 g\*=40 才值得先殺，
**8 隻時只要 g\*=16**。因為清場本身耗時，成長型在這段時間一直長。
**教訓**：**增加同類敵人的數量會改變優先級的方向，不只是改變強度。**

# 13. 「不要亂用 Metric」清單

| Metric | 適合回答 | **不適合回答** |
|---|---|---|
| TTK / Required Hits | 清場節奏、溢出浪費 | **Target Priority**（同質下幾乎無影響） |
| Action-to-Kill | AP 預算佔用 | 移動的機會成本 |
| Unit-Turns-to-Kill | 「要幾個完整回合」 | 多單位協同（分母不唯一） |
| EAtK | 玩家**主動接近**時的處理成本 | **敵人主動接敵**的情形（那是 release）；非傷害型處理 |
| TPA | 五前提下的純傷害優先級 | 接觸延遲、成長、量化平手、空間 Objective |
| EDPT | 威脅的**上界** | **實際威脅**（打不到就是 0） |
| Static Exposure | 地圖幾何的固有性質 | 當下有幾隻打得到你 |
| Effective Exposure | **當下**幾面受敵 | **未來**的包圍 |
| Release Time | 誰先構成實際威脅 | 傷害量本身 |
| Growth Rate | 未來威脅的**斜率** | 當下威脅；不同 gmode 之間不可比 |
| Threat Deadline | 時間壓力 | 玩家**是否看得出來**這個壓力 |
| Divisibility | 零頭存不存在 | 零頭**值不值錢**（要看場上有什麼） |
| Action Residue | 零頭的決策價值 | AP 可結轉時的結構性零頭（部分失效） |
| NOAR(τ) | 好選擇的**數量** | 選擇的**品質**；跨關卡比較；有對稱選項時的真實選項數 |
| Spread | 選錯的**最大代價** | 好選擇有幾個；最佳解=0 時失效 |
| Regret（相對） | 選錯代價（O>0 時） | **最佳解=0 時無定義且沉默失效**；玩家是否知道答案 |
| Regret（正規化） | 跨關卡比較容錯度 | 需先定義 Budget，否則不可比 |
| Effective Choices | 連續版「真的有幾個選項」 | 同樣受對稱污染；依賴溫度參數 |
| M1 動作組合種類 | 同單位數下的多樣性 | **跨單位數比較**（本專案 OD-26 已明載） |

# 14. 學習結論

## 14.1 「我要設計一個戰棋關卡，該觀察哪些數值？」

依觀察順序（前面的先看，因為後面的會被前面的推翻）：

```
第 0 層  maxRegret（正規化）
         一次大失誤會不會直接死？
         ↓ 這個值決定下面所有層有沒有意義（本專案 OD-20 已經付過學費）

第 1 層  Release Time 分布
         有幾隻敵人「這回合就打得到我」？
         ↓ 全部 release=0 ⇒ 空間層失效，關卡退化成排序題

第 2 層  Divisibility：EAtK mod APT
         有沒有零頭行動？
         ↓ 完全整除 ⇒ 集火是唯一解

第 3 層  TPA 的分布是否落在 Priority Boundary 的帶狀區內
         （不是追求某個精確值，是落進那條帶子）

第 4 層  NOAR(τ) 曲線 ＋ Spread（必須成對）
         ↓ 對稱合併之後才算

第 5 層  Regret 分布的形狀（不是平均值）
```

## 14.2 三句話總結

1. **目標優先級在純傷害競賽下是排序題。設計工作是讓排序失效，
   而最乾淨的做法是接觸延遲（release）—— 這在排程理論上有證明。**
2. **所有計數型指標（NOAR、動作組合種類、EffChoices）都會被對稱與組合數灌水。
   它們必須與「選錯的代價」成對使用。**
3. **指標最危險的失效不是給出錯的數字，是給出「沒問題」的數字**
   （相對 Regret 在最佳解=0 時）。

## 14.3 這輪讓我修正的三件事

| 原本以為 | 實測 |
|---|---|
| 接近成本可以一律併進 EAtK | 分成兩種：**進分母**（玩家走過去）與**釋放時間**（敵人走過來），數學性質不同 |
| TPA 相等 = 等價 | 只有 APT=1 成立 |
| 「錯誤要有代價但不該立刻死」是普遍原則 | 在本專案資料上，它與「站位有意義」直接衝突 |
