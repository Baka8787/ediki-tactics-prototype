# THIS MAP'S QUESTION
#   The sniper does not care where anybody is standing: it picks the LOWEST HP
#   unit, which is always the shrine, and shoots it from three cells away
#   through anything. Nothing on this board blocks that. 嘲諷 is the only
#   mechanism in the project that overrides an enemy target choice outright.
#
#   ⚠️ The preference is EMERGENT, not a rule: hunter = lowest HP, and any
#   player unit that drops under the shrine steals the shot. Expect the flip; it is a
#   feature of the fixture, not a bug in it.
#
# GEOMETRY — the shrine is reachable without passing the party
#   The shrine sits centre-back at (5,6). The side lanes at x=1 and x=9 let a
#   threat reach it without ever passing the party, so "who peels off" is the

# --- ONE shrine, and the reason is an instrument limit, not a design choice --
#
# 🔴 THIS MAP WAS BUILT WITH TWO PROTECT TARGETS AND MEASURED 0% ACROSS ALL
# SIXTEEN SQUADS. Two separate causes, found in that order:
#
#   1. Two 100 HP shrines against two hunter snipers. Hunter picks the LOWEST HP
#      unit, so both snipers lock the SAME shrine by definition; 2x50 a turn
#      killed it on turn 3. Fixed by dropping to one sniper and 120 HP.
#   2. Still 0%. The real cause: ObjectiveAnchor.For returns the position of the
#      FIRST protect=true unit, so every scripted strategy anchors on shrine one
#      and abandons shrine two. No squad could differ, because no squad ever
#      defended the second target at all.
#
# Cause 2 is an INSTRUMENT limit, not a statement about two-target maps. A human
# can obviously split. Until ObjectiveAnchor can hold more than one anchor, a
# two-target map is human-playtest-only and produces a dead column in any batch.
# Registered as a gap; the map is one shrine until it is closed.
spawn faction=player unit=shrine x=5 y=6 protect=true
